Was ist BlockIt?

Websites mit Werbung und verbreitete Blocker befinden sich in einem ständigen Wettrüsten: Website-Entwickler suchen Wege, öffentliche Filterlisten zu umgehen, während Blocker-Entwickler diese Listen fortlaufend aktualisieren.

BlockIt verfolgt beim Blockieren von Werbung und anderen unerwünschten Elementen einen anderen Ansatz. Statt sich nur auf gemeinsame Filterlisten zu verlassen, erstellen Sie Regeln für konkrete Elemente auf den von Ihnen besuchten Websites. Solange Sie diese Regeln nicht teilen, weiß die Website nicht, auf welche Eigenschaften sich Ihre BlockIt-Regeln stützen, und kann sie daher schwerer gezielt unwirksam machen.

Wichtige Funktionen

  • Einfache Bedienung: Sie müssen sich die Syntax von CSS-Selektoren, XPath oder BlockIt-Regeln nicht merken. Manchmal genügt es, einen Selektor aus den Entwicklertools zu kopieren und in die Erweiterung einzufügen.
  • Flexibilität:
    • Sie entscheiden, ob ein Element entfernt oder ausgeblendet wird
    • Sie entscheiden, welche Elemente blockiert und welche beibehalten werden
    • Sie entscheiden, welche Regeln Sie behalten, deaktivieren oder löschen
    • CSS-Selektoren und XPath-Ausdrücke werden unterstützt
    • Regeln werden auch innerhalb von iframes und Shadow DOM angewendet
  • Datenschutz: Alle Regeln werden lokal in Ihrem Browser gespeichert und nirgendwohin gesendet.
  • BlockIt-Syntax: In komplexen Fällen kann eine Syntax verwendet werden, die Standard-CSS-Selektoren erweitert. Bei Bedarf finden Sie Einzelheiten in der Dokumentation zur BlockIt-Syntax.
  • Gruppierung nach Website: Regeln werden automatisch für die aktuelle Website und für alle übrigen Websites gruppiert, was die Verwaltung erleichtert.
  • Einstellungen teilen: Exportieren Sie Ihre Regeln in eine Datei, um sie mit anderen zu teilen.
  • Mehrsprachigkeit: Die Erweiterung verwendet die Sprache Ihres Browsers. Unterstützt werden Russisch, Englisch, Französisch, Deutsch, Spanisch, Portugiesisch, Chinesisch und Japanisch. Ist Ihre Sprache nicht verfügbar, wird die Oberfläche auf Englisch angezeigt.
  • Open Source: Die Erweiterung wird unter der BSD-3-Clause-Lizenz entwickelt. Sie können mitwirken, Verbesserungen vorschlagen und den Code auf GitHub einsehen.

Tipps zur Auswahl des zu blockierenden Elements

Bestimmen Sie vor dem Kopieren eines Selektors oder HTML-Codes genau, welches Element blockiert werden soll.

  • Nutzen Sie die Hervorhebung der Entwicklertools. Fahren Sie über HTML-Zeilen, um die zugehörigen Seitenelemente hervorzuheben und genau zu sehen, welcher Bereich blockiert wird.
  • Wählen Sie das äußerste Element ohne unnötigen Inhalt. Suchen Sie den äußersten Container, der nur den benötigten Block enthält. Ein zu tief liegendes Element kann einen Teil der Werbung sichtbar lassen; ein zu weit gefasstes kann nützliche Inhalte ausblenden.
  • Beachten Sie die Elementzahl. BlockIt zeigt nach dem Einfügen einer Regel die Trefferzahl. Ein Treffer ist gewöhnlich sicherer. Mehrere Treffer sind in Ordnung, wenn Sie alle geprüft haben; 0 bedeutet, dass die Regel nichts findet.

Blockiert eine Regel zu viel oder gar nichts, löschen Sie sie und wählen Sie im HTML-Baum ein anderes Element weiter oben oder unten.

Blockiermodi

  • Entfernen: entfernt das Element aus dem HTML und gibt seinen Platz frei. Das funktioniert meist gut, kann aber gelegentlich das Layout verändern.
  • Ausblenden: macht das Element unsichtbar, erhält aber seinen Platz. Verwenden Sie dies, wenn die Seite nach dem Entfernen schlechter aussieht.

Möglichkeiten, eine Regel zu erstellen Nach oben

Suchen Sie das Element zunächst in den Entwicklertools und sehen Sie sich Tag, Klassen und Attribute an.

Was könnte helfen?

Aktivieren Sie die passenden Hinweise. Die Hervorhebung blendet andere Methoden nicht aus, sondern schlägt nur einen sinnvollen Ausgangspunkt vor.

Empfohlene Methoden werden unten hervorgehoben. Wählen Sie eine Methode, um die ausführliche Anleitung zu öffnen.

1CSS-Selektor aus den Entwicklertools kopieren Zum Lesen auswählen

Beginnen Sie hier, um schnell zu testen, ob ein Standardselektor das Element blockieren kann. Die Entwicklertools erstellen ihn automatisch: Element auswählen, dann „Kopieren“ / “Copy” → „selector kopieren“ / “Copy selector”.

Fügen Sie den Selektor in das Hauptfeld von BlockIt ein, prüfen Sie die Trefferzahl und fügen Sie die Regel hinzu. Wird sie nach dem Neuladen unzuverlässig, verwenden Sie StableHTMLFinder oder den Regelkonstruktor.

1
2XPath aus den Entwicklertools kopieren Zum Lesen auswählen

XPath beschreibt den Pfad zu einem Element durch die Seitenstruktur. Das kann helfen, wenn Klassen und andere Attribute instabil sind, der Pfad selbst jedoch gleich bleibt. Wählen Sie in den Entwicklertools „XPath kopieren“ / “Copy XPath” und fügen Sie den Ausdruck in BlockIt ein.

Prüfen Sie den kopierten Ausdruck. Chrome kann XPath um eine id aufbauen. Ändert sich diese ID, ist auch XPath instabil. Ein absoluter Pfad mit Positionsnummern bricht, wenn sich die HTML-Struktur ändert.

BlockIt wertet XPath getrennt im Hauptdokument und in jedem iframe aus; ein innerhalb eines iframe kopierter XPath kann daher funktionieren. Browser werten XPath nicht über eine Shadow-DOM-Grenze hinweg aus. Verwenden Sie dort den Regelkonstruktor oder StableHTMLFinder, um eine CSS-basierte oder erweiterte BlockIt-Regel zu erstellen.

1
3Schnellregel aus HTML erstellen Zum Lesen auswählen

Diese Methode bietet mehr Kontrolle als ein fertiger Selektor aus den Entwicklertools: Nach dem Analysieren des HTML wählen Sie selbst, welche Attribute in den Selektor aufgenommen werden.

1
Übernehmen Sie nicht automatisch jedes Attribut. Eine Klasse oder ID aus zufällig wirkenden Zeichen kann sich beim nächsten Laden ändern.
4StableHTMLFinder verwenden Zum Lesen auswählen

StableHTMLFinder hilft, wenn Klassen und IDs verschleiert sind, sich zwischen Ladevorgängen ändern oder die Seite viele ähnliche Blöcke enthält. Das ist oft einfacher als eine manuelle HTML-Analyse, benötigt aber Zeit, weil die Erweiterung die Seite mehrfach laden muss.

1

StableHTMLFinder blockiert selbst keine Elemente. Es hilft Ihnen, die Grundlage für eine BlockIt-Regel zu wählen:

  • CSS-Selektor — die einfachste Wahl, wenn er stabile Eigenschaften nutzt und die richtige Elementzahl findet.
  • BlockIt-Regel — wenn ein genauer Treffer erweiterte, in Standard-CSS nicht verfügbare Syntax benötigt.
  • Karte selbst untersuchen — stabile Eigenschaften des Elements und seiner Umgebung prüfen und in den Regelkonstruktor von BlockIt übertragen, wenn die erzeugten Ergebnisse nicht präzise genug sind.
5Regelkonstruktor öffnen Zum Lesen auswählen

Der Regelkonstruktor ist ein leistungsfähiges Werkzeug für präzise Regeln, ohne dass Sie CSS, XPath oder die BlockIt-Syntax kennen müssen. Er eignet sich für stabile wie instabile Elemente: Statt einer konkreten Klasse kann eine Regel Text, Attribut- oder Klassenanzahl, Geschwisterposition und umgebende Elemente verwenden.

Kopieren Sie in den Entwicklertools das HTML des Elements, öffnen Sie den „Erweiterten Modus“ von BlockIt, fügen Sie das HTML in das entsprechende Feld ein und klicken Sie auf „Regelkonstruktor öffnen“.

Elementkarte

Jede Karte beschreibt ein HTML-Element: Tag, Attributanzahl sowie Bedingungen für Attribute, Text und Position.

Beziehungsbaum

Vorfahren stehen oben, Nachfahren eingerückt darunter. Geschwister befinden sich auf derselben Verschachtelungsebene.

Stabile Eigenschaften

Automatisch eingefügte Werte lassen sich deaktivieren. Verwenden Sie wechselnde IDs und Klassen nicht nur deshalb, weil sie im HTML gefunden wurden.

Prüfung

Prüfen Sie sofort die Trefferzahl und anschließend mit „Nach dem Neuladen prüfen“, ob das Ergebnis stabil bleibt.

In einer Karte verfügbare Bedingungen

  • Tag: angeben oder leer lassen, wenn er nicht wichtig ist.
  • Attributanzahl: genau, mindestens oder höchstens die angegebene Zahl.
  • Attribute: Bedingungen für Namen und Werte; bei class kann auch die Klassenanzahl festgelegt werden.
  • Text: eigener Text des Elements oder gesamter Text darin; genaue Übereinstimmung, Anfang, Ende, Teilzeichenfolge oder regulärer Ausdruck.
  • Geschwisterposition: Position des Elements unter den Kindern desselben Elternelements.

Verwandte Elemente

Dem Zielelement und seinen Vorfahren können ein direktes Elternelement oder beliebige Vorfahren hinzugefügt werden. Das Ziel kann außerdem ein Kind, einen Nachfahren oder ein Geschwister haben; Geschwister können eigene Nachfahren besitzen. Für verwandte Elemente gibt es den Schalter „Darf fehlen“.

Geschwisterposition ist der Platz eines Elements unter den Kindern eines Elternelements. Position in den Regelergebnissen ist sein Platz unter allen von der vollständigen Regel gefundenen Elementen. Das sind unterschiedliche Bedingungen.

Vorschau und Prüfung

Lesen Sie die verständliche Beschreibung unter „Regelvorschau“. So erkennen Sie versehentlich hinzugefügte Attribute, Textbedingungen oder Beziehungen. Prüfen Sie danach die Trefferzahl auf der aktuellen Seite und nach dem Neuladen.

Beispiel: eine Regel für mehrere Elemente einrichten

  1. Aktivieren Sie „Geschwisterposition“ und geben Sie die Positionen der gewünschten Elemente ein: in diesem Beispiel 2, 3 und 5.
  2. Behalten Sie für den Namen des Attributs class die genaue Übereinstimmung bei.
  3. Entfernen Sie den unzuverlässigen Teil des Klassenwerts und ändern Sie „Wert: genau“ in „Wert: enthält“.
  4. Deaktivieren Sie „Klassenanzahl“, wenn diese Zahl unwichtig ist und sich ändern kann.
  5. Lesen Sie die „Regelvorschau“ und prüfen Sie, ob jede Bedingung nötig ist.
  6. Schließen Sie die Entwicklertools auf der Zielseite und klicken Sie auf „Nach dem Neuladen prüfen“. Manche Websites laden bei geöffneten Entwicklertools andere Inhalte.
  7. Vergewissern Sie sich, dass sich die Trefferzahl nach dem Neuladen nicht ändert. Das spricht für eine stabile Regel.
  8. Klicken Sie auf „Regel erstellen“.
1

Wann Sie die Methode wechseln sollten

Beginnen Sie für ein schnelles Ergebnis mit einem CSS-Selektor aus den Entwicklertools. Eine HTML-Schnellregel ist sinnvoll, wenn die Eigenschaften stabil wirken, Sie aber die verwendeten Attribute selbst bestimmen möchten. Sind die Eigenschaften instabil oder zufällig oder enthält die Seite viele ähnliche Blöcke, verwenden Sie StableHTMLFinder oder den Regelkonstruktor.

CSS-Selektoren im Überblick Nach oben

Was sind Selektoren?

Selektoren finden ein Element auf einer Webseite anhand seiner Eigenschaften: Tag, Klasse, Kennung, Attribute oder Position in der HTML-Struktur.

In CSS-Styles wenden Selektoren Formatierungen an. In BlockIt dienen sie nur zum Finden von Elementen. Wir legen keine Farben, Schriften oder Abstände fest, sondern finden ein Element, um es zu blockieren.

Diese Beispiele helfen Ihnen, gewöhnliche CSS-Selektoren zu lesen und leicht zu bearbeiten.

Selektor prüfen

  1. Öffnen Sie in den Entwicklertools den Tab „Elemente“ / “Elements”.
  2. Drücken Sie Ctrl + F oder auf dem Mac Cmd + F.
  3. Fügen Sie den Selektor in das Suchfeld ein.
  4. Die Entwicklertools markieren alle Treffer und zeigen deren Anzahl, zum Beispiel 1 of 3.
1

Selektortypen

Universalselektor (*)

Findet alle Elemente der Seite. Verwenden Sie ihn mit Bedacht: Er liefert alles, was im HTML vorhanden ist.

Selektor: *

Was er findet: ausnahmslos alle Elemente.

Tag-Selektor

Findet alle Elemente mit dem angegebenen HTML-Tag.

Selektoren: h1, p, button, div

Gefundene Elemente:

  • h1 — alle Überschriften erster Ebene;
  • p — alle Absätze;
  • button — alle Schaltflächen;
  • div — alle <div>-Container.

Klassenselektor (.Klasse)

Findet alle Elemente mit der angegebenen Klasse im Attribut class. Mehrere Klassen werden ohne Leerzeichen aneinandergereiht.

Selektoren: .card, .card__title, .card.featured

Gefundene Elemente:

  • .card — alle Elemente mit der Klasse card;
  • .card__title — alle Elemente mit der Klasse card__title;
  • .card.featured — Elemente, die zugleich die Klassen card und featured besitzen.

Ein Element darf weitere Klassen enthalten: class="card featured compact" entspricht ebenfalls .card.featured. Für eine genaue Übereinstimmung der gesamten Klassenfolge eignet sich [class="card featured"]; dieser Selektor hängt jedoch von der Reihenfolge ab und erlaubt keine zusätzlichen Klassen.

ID-Selektor (#id)

Findet ein Element mit einer eindeutigen id. Auf einer Seite sollte es nur ein Element mit dieser ID geben.

Selektoren: #salad-cat, #confused-cat, #bread-cat

Gefundene Elemente:

  • #salad-cat — das Element mit id="salad-cat";
  • #confused-cat — das Element mit id="confused-cat";
  • #bread-cat — das Element mit id="bread-cat".

Attributselektor ([attribut="wert"])

Ein Attribut kann auf einen genauen Wert oder nur auf sein Vorhandensein geprüft werden. Mehrere Bedingungen werden direkt aneinandergereiht.

Selektoren: [data-type], [data-type="description"], [data-type="description"][aria-label="Card"], [class~="card"], [class="card featured"]

Gefundene Elemente:

  • [data-type] — Elemente mit einem data-type-Attribut mit beliebigem Wert;
  • [data-type="description"] — Elemente, deren data-type-Wert genau description ist;
  • [data-type="description"][aria-label="Card"] — Elemente, bei denen beide Attribute übereinstimmen;
  • [class~="card"] — Elemente, deren Klassenliste die einzelne Klasse card enthält;
  • [class="card featured"] — Elemente, deren gesamtes class-Attribut genau der angegebenen Zeichenfolge entspricht.
Möglichkeiten zum Vergleichen eines Werts
[href^="https://"]
der Wert beginnt mit https://
[src$=".png"]
der Wert endet mit .png
[class*="advert"]
der Wert enthält advert an beliebiger Stelle
[class~="card"]
eine durch Leerzeichen getrennte Wortliste enthält das einzelne Wort card
[lang|="en"]
der Wert ist en oder beginnt mit en-, zum Beispiel en-US
[aria-label*="advertisement" i]
der Wert enthält „advertisement“, unabhängig von Groß- und Kleinschreibung

Ein Selektor prüft nur die aufgeführten Attribute und verbietet keine weiteren. So findet [data-type="description"][aria-label="Card"] auch <div data-type="description" aria-label="Card" title="Details">: Das zusätzliche Attribut title verhindert den Treffer nicht. Ein gewöhnlicher CSS-Selektor kann nicht verlangen, dass keine weiteren Attribute vorhanden sind.

Kombinierte Selektoren

Tag, Klasse, ID und Attributbedingungen lassen sich ohne Leerzeichen kombinieren, damit alle Eigenschaften dasselbe Element betreffen.

Selektoren: h2.card__title, div.card.featured, div[data-type="description"], article.card[data-type="advertisement"][aria-label="Advertisement"]

Gefundene Elemente:

  • h2.card__title — ein <h2> mit der Klasse card__title;
  • div.card.featured — ein <div> mit den Klassen card und featured; weitere Klassen sind erlaubt;
  • div[data-type="description"] — ein <div> mit dem angegebenen Attribut; weitere Attribute sind erlaubt;
  • article.card[data-type="advertisement"][aria-label="Advertisement"] — ein <article> mit der Klasse card, dessen Attributwerte genau data-type="advertisement" und aria-label="Advertisement" entsprechen.

Nachfahrenselektor (Leerzeichen)

Findet Elemente, die auf beliebiger Verschachtelungsebene innerhalb eines anderen Elements liegen.

Selektor: .card .btn

Was er findet: alle Elemente mit der Klasse btn innerhalb eines Elements mit der Klasse card.

Kindselektor (>)

Findet Elemente, die direkte Kinder eines anderen Elements sind. Die Suche geht nur eine Ebene tief.

Selektor: .card__body > .card__title

Was er findet: Elemente mit der Klasse card__title, die direkte Kinder eines Elements mit der Klasse card__body sind.

Angrenzender-Geschwister-Selektor (+)

Findet das Element, das auf derselben Verschachtelungsebene das nächste Geschwisterelement eines anderen Elements ist.

Selektor: #confused-cat + .card__description

Was er findet: ein <p>, das unmittelbar auf das Element mit id="confused-cat" folgt.

Positions-Pseudoklasse

Wählt Elemente nach ihrer Position unter Geschwistern aus.

Selektor: .card__actions :nth-child(2)

Was er findet: das zweite Kind innerhalb eines Elements mit der Klasse card__actions.

Gewöhnliche CSS-Selektoren haben Grenzen. Sie können ohne Aufzählung weder die Anzahl von Attributen oder Klassen noch eigenen oder beliebigen enthaltenen Text, reguläre Ausdrücke oder Muster für Attributnamen beschreiben. [data-*] ist beispielsweise kein Standard-CSS-Selektor. Für solche Fälle dienen BlockIt-Regeln, die CSS um Konstruktionen wie [data-*], :attr-name(/^data-/) und weitere Bedingungen erweitern. Dokumentation zur BlockIt-Syntax lesen.

Was sind iframe und Shadow DOM? Nach oben

iframe ist eine eigenständige Webseite, die in eine andere Seite eingebettet ist. Ihr Inhalt liegt in einem eigenen Dokument; eine gewöhnliche Suche von der übergeordneten Seite kann diese Grenze daher nicht einfach überschreiten.

So sieht ein iframe in HTML aus 
<main>
  <h1>Hauptseite</h1>
  <iframe src="advertisement.html"></iframe>
</main>

Das Markup aus advertisement.html wird als eigenes Dokument im <iframe> geladen.

Shadow DOM ist der isolierte interne Baum einer Komponente. Websites trennen damit das Markup der Komponente vom Rest der Seite; eine geschlossene Shadow Root verbirgt diesen Baum zusätzlich vor gewöhnlichen Seitenskripten.

So sieht Shadow DOM in den Entwicklertools aus 
<video-player>
  #shadow-root (open)
    <button class="play">Wiedergabe</button>
</video-player>

Die Schaltfläche liegt in der Shadow Root der Komponente <video-player>, nicht im gewöhnlichen Baum der Hauptseite.

Für Blocker entstehen dadurch Suchgrenzen: Eine Regel muss nicht nur im Hauptdokument, sondern auch in jedem zugänglichen iframe und jeder Shadow Root ausgeführt werden. Nicht jeder Blocker tut das. BlockIt wendet CSS-Selektoren und erweiterte Regeln in iframe und Shadow DOM an; XPath funktioniert jedoch nur in Dokumenten und überschreitet keine Shadow-DOM-Grenze.

Regeln verwalten Nach oben

Erstellte Regeln erscheinen in der Liste für die aktuelle Website oder in der Liste der Regeln ohne Domainbindung. Regeln aus dem Konstruktor können bearbeitet oder gelöscht werden; deaktivierte Regeln bleiben entsprechend gekennzeichnet in der Liste.

Deaktivieren und Löschen

Wie deaktiviere ich eine Regel?

Suchen Sie die Regel unter „Aktive Regeln“ und klicken Sie auf „Deaktivieren“. Sie bleibt mit der Kennzeichnung „Deaktiviert“ an ihrem Platz, wird aber nicht mehr angewendet. Hat sie bereits ein Element von der geöffneten Seite entfernt, laden Sie die Seite neu.

Wie lösche ich eine Regel?

Suchen Sie die Regel unter „Aktive Regeln“ und klicken Sie auf „Löschen“. Laden Sie die Seite mit F5 oder der Aktualisieren-Schaltfläche neu, um ein bereits entferntes Element wiederherzustellen.

Export und Import

Beim Export werden Regeln in einer Datei gespeichert. Der Import fügt Regeln aus einer solchen Datei hinzu oder ersetzt damit die aktuelle Liste. So können Einstellungen übertragen und zwischen Geräten ausgetauscht werden.

1

Regeln prüfen

Öffnen Sie die zu prüfende Seite und danach BlockIt. Klicken Sie in der Überschrift „Für diese Website: <Domain>“ auf „Regeln prüfen“.

Die Prüfung zeigt, ob gespeicherte Regeln Elemente auf der geöffneten Seite finden. Sie können einmal messen oder „Stabilität prüfen“ aktivieren und mehrere Neuladungen wählen. Dabei setzt BlockIt die Regeln vorübergehend aus, lädt die Seite neu und zeigt bei jedem Laden die Trefferzahl jeder Regel.

  • Funktioniert: Die Regel findet bei jeder Prüfung dieselbe, von null verschiedene Elementzahl.
  • Instabil: Die Regel findet Elemente, deren Anzahl sich jedoch zwischen Ladevorgängen ändert.
  • Nicht funktioniert: Auf der geprüften Seite wurden keine Treffer gefunden.
  • Fehler: Die Regel konnte nicht ausgeführt werden.

Geprüft werden Regeln der aktuellen Basisdomain und Regeln ohne Domainbindung. BlockIt trennt bei der normalen Bindung keine Subdomains: Eine auf e.mail.ru erstellte Regel wird etwa für mail.ru gespeichert. Geprüft werden aber die Elemente genau der Seite, von der aus Sie die Diagnose öffnen. Eine auf einer Subdomain funktionierende Regel kann daher auf einer anderen Subdomain oder URL „Nicht funktioniert“ erhalten. Öffnen Sie für ein verlässliches Ergebnis die Seite, für die die Regel erstellt wurde.

Die Prüfung bewertet Treffer, nicht den Zweck der Elemente. Ein Ergebnis ungleich null bedeutet, dass die Regel etwas gefunden hat, garantiert aber nicht, dass es nur die gewünschten Elemente sind. Vergleichen Sie Trefferzahl und Ergebnis auf der Seite.

Problemlösung Nach oben

Zusammen mit der Werbung wurde etwas anderes blockiert

Das passiert, wenn der Selektor zu weit gefasst ist und neben der Werbung weitere Seitenelemente findet.

Was Sie tun können:

  • Löschen Sie die Regel wie unter „Regeln verwalten“ beschrieben.
  • Wählen Sie ein genaueres Element: Gehen Sie im HTML-Baum nach oben oder unten und suchen Sie einen Container, der nur die Werbung enthält.
  • Prüfen Sie vor dem Hinzufügen die Trefferzahl. Mehrere Treffer sind nur richtig, wenn jedes gefundene Element blockiert werden soll.
Die erstellte Regel hat nicht funktioniert
  • Mögliche Ursache 1: Nicht das äußerste Element wurde gewählt. Gehen Sie im HTML-Baum weiter nach oben und kopieren Sie den Selektor des übergeordneten Containers.
  • Mögliche Ursache 2: Die Website verwendet dynamische Klassen (Verschleierung). Ein kopierter Selektor kann nach dem Neuladen ausfallen. Markieren Sie unter „Möglichkeiten, eine Regel zu erstellen“ die Eigenschaften als instabil und verwenden Sie eine empfohlene Methode, etwa StableHTMLFinder oder den Konstruktor.
  • Mögliche Ursache 3: Die Seite hat ihre Struktur nach dem Erstellen der Regel geändert. Prüfen Sie das aktuelle HTML und die Trefferzahl. Wurde der Block umgebaut, kopieren Sie den Selektor erneut oder verfeinern Sie die Regel im Konstruktor.
  • Mögliche Ursache 4: Die Regel wurde für eine andere Domain erstellt. Prüfen Sie, ob sie unter „Für diese Website“ oder „Für andere Websites“ steht.
Der Selektor findet kein Element
  • Prüfen Sie den Selektor: Öffnen Sie die Entwicklertools (F12), wechseln Sie zum Tab „Elemente“ / “Elements”, drücken Sie Ctrl + F (auf dem Mac Cmd + F) und geben Sie den Selektor ein. Findet die Suche nichts, ist der Selektor falsch.
Nach dem Entfernen ist das Layout beschädigt und sieht schlechter aus
  • Lösung: Löschen Sie die Regel und erstellen Sie sie im Modus „Ausblenden“ neu. Dadurch bleibt der Platz des Elements erhalten und das Layout wird nicht verschoben.
Der Selektor findet zu viele Elemente

Prüfen Sie zuerst die Trefferzahl und die gefundenen Elemente. Besitzt das gewünschte Element eine stabile Klasse oder ein stabiles Attribut, ergänzen Sie es im Selektor. Reicht ein einfacher Selektor nicht, verwenden Sie den Regelkonstruktor: Er kann Text, Klassen- und Attributanzahl, Geschwisterposition und Beziehungen zur Umgebung berücksichtigen. Prüfen Sie die verfeinerte Regel auf der aktuellen Seite und nach dem Neuladen.

Die HTML-Struktur der Seite ist unverständlich

Verwenden Sie StableHTMLFinder: Die Erweiterung vergleicht mehrere Ladevorgänge und erstellt eine Stabilitätskarte. Suchen Sie dort das Element und untersuchen Sie seine stabilen Eigenschaften und seine Umgebung.

Wirkt das Markup besonders stark verschleiert, liefert die Website VPN-Verbindungen möglicherweise eine andere Seitenvariante. Falls möglich, deaktivieren Sie das VPN vorübergehend, laden Sie neu und wiederholen Sie die Analyse. Das hilft nicht überall, zeigt aber, ob die kompliziertere Struktur mit der gelieferten Seitenvariante zusammenhängt.

Nichts hilft

Kombinieren Sie die von StableHTMLFinder ermittelten stabilen Eigenschaften mit dem BlockIt-Konstruktor. So erstellen Sie manuell eine Regel, die Element und Umgebung berücksichtigt.

Funktioniert die Regel trotz verschiedener Versuche nicht oder meldet die Erweiterung Fehler, senden Sie über das Feedback-Formular einen Bericht. Geben Sie Seitenadresse und Regel an und fügen Sie möglichst Screenshots bei.
