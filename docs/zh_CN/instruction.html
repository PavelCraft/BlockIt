什么是 BlockIt？

展示广告的网站与常见拦截器一直在竞争：网站开发者设法绕过公开过滤列表，而拦截器开发者不断更新这些列表。

BlockIt 采用不同的方式。您可以为常用网站上的特定元素自行创建规则，而不是只依赖共享列表。只要不主动分享规则，网站就不知道规则依赖哪些特征，也更难故意使其失效。

主要功能

  • 易于使用：无需记住 CSS 选择器、XPath 或 BlockIt 规则语法。有时从开发者工具复制选择器并粘贴即可。
  • 灵活：
    • 自行选择删除元素还是将其隐藏
    • 自行选择屏蔽或保留哪些元素
    • 自行选择保留、禁用或删除哪些规则
    • 支持 CSS 选择器和 XPath 表达式
    • 规则也可应用于 iframe 和 Shadow DOM 内部
  • 隐私：所有规则都保存在浏览器本地，不会发送到任何地方。
  • BlockIt 语法：复杂情况可以使用扩展标准 CSS 的语法。需要时可查看 BlockIt 语法文档。
  • 按网站分组：规则自动分为当前网站和其他网站两组。
  • 分享设置：可将规则导出到文件。
  • 多语言：扩展程序跟随浏览器语言，支持俄语、英语、法语、德语、西班牙语、葡萄牙语、中文和日语；不支持时显示英语。
  • 开源：采用 BSD-3-Clause 许可证开发。您可以在 GitHub 查看代码、参与开发或提出建议。

选择要屏蔽元素的建议

复制选择器或 HTML 前，请准确确定要屏蔽的元素。

  • 使用开发者工具的高亮。将鼠标移到 HTML 行上，查看对应区域。
  • 选择不包含多余内容的最外层元素。层级太深可能留下部分广告，范围太大则可能隐藏有用内容。
  • 留意元素数量。通常 1 个更安全；如果逐一检查过，也可以有多个；0 表示规则找不到内容。

如果屏蔽过多或完全无效，请删除规则，并在 HTML 树中选择更高或更低层级的元素。

屏蔽模式

  • 删除：从 HTML 中移除元素并释放空间，有时会改变布局。
  • 隐藏：保留空间但让元素不可见。删除后布局变差时使用。

先在开发者工具中找到元素，并检查标签、类和属性。

哪种方法可能有用？

推荐方法会在下方高亮。选择任意方法可查看详细说明。

1从开发者工具复制 CSS 选择器 选择以阅读

粘贴到 BlockIt，检查匹配数并添加规则。如果刷新后不可靠，请使用 StableHTMLFinder 或规则构建器。

2从开发者工具复制 XPath 选择以阅读

XPath 描述页面结构中通往元素的路径。当属性不稳定但路径不变时很有用。选择“复制 XPath” / “Copy XPath”，然后粘贴到 BlockIt。

检查复制的表达式。Chrome 可能以 id 为基础；ID 变化时 XPath 也不稳定。带位置编号的绝对路径会因结构变化而失效。

BlockIt 会在主文档和每个 iframe 中分别计算 XPath，因此从 iframe 内复制的 XPath 可能有效。XPath 无法跨越 Shadow DOM 边界；这时请使用规则构建器或 StableHTMLFinder。

稳定特征

可以禁用自动填入的值。不要仅因为 HTML 中存在变化的 ID 或类就使用它们。

检查

先检查匹配数量，再用“刷新后检查”确认结果保持稳定。

卡片中可用的条件

  • 标签：可以指定；如果不重要，也可以留空。
  • 属性数量：可以要求恰好、至少或至多为指定数量。
  • 属性：可为名称和值设置条件；对于 class，还可以指定类的数量。
  • 文本：可检查元素自身文本或内部全部文本，并使用精确匹配、前缀、后缀、子字符串或正则表达式。
  • 兄弟位置：元素在同一父元素的子元素中的位置。

关联元素

可以为目标元素及其祖先添加直接父元素或任意祖先。目标元素也可以包含子元素、后代或兄弟元素，兄弟元素还可拥有自己的后代。关联元素带有“允许不存在”开关。

兄弟位置是元素在同一父元素的子元素中的位置；规则结果中的位置则是它在完整规则找到的所有元素中的位置。这是两个不同条件。

预览与检查

请阅读“规则预览”中的文字说明，它能帮助发现误加的属性、文本条件或关系。然后在当前页面和刷新后分别检查匹配数量。

示例：用一条规则配置多个元素

  1. 启用“兄弟位置”，输入目标元素的位置；本例为 2、3 和 5。
  2. 保留对 class 属性名称的精确匹配。
  3. 删除类值中不可靠的部分，并将“值：精确”等改为“值：包含”。
  4. 如果类数量并不重要且可能变化，请禁用“类数量”。
  5. 阅读“规则预览”下的说明，确认每个条件都确有必要。
  6. 关闭目标页面上的开发者工具，再单击“刷新后检查”。开发者工具打开时，某些网站会加载不同内容。
  7. 确认刷新后匹配数量没有变化，这说明规则较为稳定。
  8. 单击“创建规则”。
1

何时改用其他方法

若想快速获得结果，可先尝试开发者工具中的 CSS 选择器。如果元素特征看起来稳定，但您想控制要使用哪些属性，可使用 HTML 快速规则。如果特征不稳定、像随机生成，或页面上有许多相似区块，请使用 StableHTMLFinder 或规则构建器。

CSS 选择器速查 返回顶部

什么是选择器？

选择器通过标签、类、标识符、属性或在 HTML 结构中的位置来查找网页元素。

在 CSS 样式中，选择器用于应用格式；在 BlockIt 中，选择器只负责查找元素。这里不会设置颜色、字体或间距，而只是找到元素并将其屏蔽。

下面的示例可帮助您读懂普通 CSS 选择器并进行简单修改。

如何检查选择器

  1. 在开发者工具中打开“元素” / “Elements”标签页。
  2. 按 Ctrl + F；Mac 上按 Cmd + F。
  3. 将选择器粘贴到搜索框。
  4. 开发者工具会高亮所有匹配项并显示数量，例如 1 of 3。
1

选择器类型

通用选择器（*）

查找页面上的所有元素。请谨慎使用：它会返回 HTML 中的一切。

选择器： *

找到：所有元素，无一例外。

标签选择器

查找具有指定 HTML 标签的所有元素。

选择器： h1、p、button、div

找到：

  • h1 — 所有一级标题；
  • p — 所有段落；
  • button — 所有按钮；
  • div — 所有 <div> 容器。

类选择器（.class）

查找 class 属性中包含指定类的所有元素。多个类之间不要加空格。

选择器： .card、.card__title、.card.featured

找到：

  • .card — 所有带 card 类的元素；
  • .card__title — 所有带 card__title 类的元素；
  • .card.featured — 同时带 card 和 featured 类的元素。

元素还可以有其他类：例如 class="card featured compact" 也符合 .card.featured。若要精确匹配完整类字符串，可使用 [class="card featured"]，但它依赖类的顺序，也不允许额外类。

ID 选择器（#id）

查找具有唯一 id 的元素。一个页面中应只有一个元素使用该 ID。

选择器： #salad-cat、#confused-cat、#bread-cat

找到：

  • #salad-cat — id="salad-cat" 的元素；
  • #confused-cat — id="confused-cat" 的元素；
  • #bread-cat — id="bread-cat" 的元素。

属性选择器（[attribute="value"]）

既可以检查属性的精确值，也可以只检查属性是否存在。多个条件直接连写。

选择器： [data-type]、[data-type="description"]、[data-type="description"][aria-label="Card"]、[class~="card"]、[class="card featured"]

找到：

  • [data-type] — 带有任意值的 data-type 属性的元素；
  • [data-type="description"] — data-type 的值恰好是 description 的元素；
  • [data-type="description"][aria-label="Card"] — 两个属性都匹配的元素；
  • [class~="card"] — 类列表中包含独立的 card 类的元素；
  • [class="card featured"] — 整个 class 属性恰好等于给定字符串的元素。
比较属性值的方法
[href^="https://"]
值以 https:// 开头
[src$=".png"]
值以 .png 结尾
[class*="advert"]
值中任意位置包含 advert
[class~="card"]
以空格分隔的词中包含独立的 card
[lang|="en"]
值为 en，或以 en- 开头，例如 en-US
[aria-label*="advertisement" i]
值包含 advertisement，不区分大小写

选择器只检查列出的属性，不排除其他属性。例如，[data-type="description"][aria-label="Card"] 也会找到 <div data-type="description" aria-label="Card" title="Details">：额外的 title 不影响匹配。标准 CSS 无法要求元素没有任何其他属性。

组合选择器

标签、类、ID 和属性条件可以不加空格直接组合，让所有条件作用于同一个元素。

选择器： h2.card__title、div.card.featured、div[data-type="description"]、article.card[data-type="advertisement"][aria-label="Advertisement"]

找到：

  • h2.card__title — 带 card__title 类的 <h2>；
  • div.card.featured — 同时带 card 和 featured 类的 <div>；可以有其他类；
  • div[data-type="description"] — 带指定属性的 <div>；可以有其他属性；
  • article.card[data-type="advertisement"][aria-label="Advertisement"] — 带 card 类、且两个属性值分别精确等于 advertisement 和 Advertisement 的 <article>。

后代选择器（空格）

查找位于另一元素内部任意层级的元素。

选择器： .card .btn

找到：位于带 card 类的元素内部、带 btn 类的所有元素。

直接子元素选择器（>）

查找另一元素的直接子元素，只向下一层搜索。

选择器： .card__body > .card__title

找到：作为带 card__body 类的元素直接子元素、且带 card__title 类的元素。

相邻兄弟选择器（+）

查找同一层级中紧跟在另一元素之后的兄弟元素。

选择器： #confused-cat + .card__description

找到：紧跟在 id="confused-cat" 元素之后、带 card__description 类的元素。

位置伪类

按元素在兄弟元素中的位置进行选择。

选择器： .card__actions :nth-child(2)

找到：带 card__actions 类的元素内部的第二个子元素。

标准 CSS 选择器有局限。它无法在不逐一列出的情况下描述属性或类的数量，也无法描述元素自身文本、任意内部文本、正则表达式或属性名称模式。例如，[data-*] 不是标准 CSS。此类情况可使用扩展 CSS 语法的 BlockIt 规则，例如 [data-*]、:attr-name(/^data-/) 等。阅读 BlockIt 语法文档。

什么是 iframe 和 Shadow DOM？返回顶部

iframe 是嵌入在另一网页中的独立网页。它有自己的文档，因此从父页面进行的普通搜索不能直接进入其中。

iframe 在 HTML 中的样子 
<main>
  <h1>主页面</h1>
  <iframe src="advertisement.html"></iframe>
</main>

advertisement.html 的标记会作为独立文档加载到 <iframe> 中。

Shadow DOM 是组件内部隔离的元素树。网站用它将组件标记与页面其他部分分开；封闭的影子根还会对普通页面脚本隐藏该树。

Shadow DOM 在开发者工具中的样子 
<video-player>
  #shadow-root (open)
    <button class="play">播放</button>
</video-player>

按钮位于 <video-player> 组件的影子根中，而非主页面的普通元素树中。

这些结构为拦截器形成搜索边界：规则不仅要在主文档中运行，还要在可访问的 iframe 和影子根中运行。并非所有拦截器都能做到。BlockIt 可在 iframe 和 Shadow DOM 中应用 CSS 选择器及扩展规则，但 XPath 只在文档中有效，不能跨越 Shadow DOM 边界。

管理规则 返回顶部

已创建的规则会显示在当前网站的列表中，或显示在不绑定域名的规则列表中。构建器创建的规则可以编辑或删除；禁用的规则仍保留在列表中，并带有相应标记。

禁用与删除

如何禁用规则？

在“活动规则”中找到该规则并单击“禁用”。规则仍保留，但不再应用，并显示“已禁用”标记。如果它已从当前页面删除某个元素，刷新页面即可恢复原始内容。

如何删除规则？

在“活动规则”中找到该规则并单击“删除”。若要恢复已从页面移除的元素，请按 F5 或单击标签页的刷新按钮。

导出与导入

导出会将规则保存到文件；导入可以从文件添加规则，也可以替换当前列表。您可以借此迁移设置或在设备间共享。

1

检查规则

打开要检查的页面，再打开 BlockIt。在“此网站：<域名>”分组标题中单击“检查规则”。

检查会显示已保存规则能否在当前页面找到元素。您可以检查一次，也可以启用“检查稳定性”并指定多次刷新。检查期间，BlockIt 会暂时停止应用规则、刷新页面，并显示每次加载时各规则的匹配数量。

  • 有效：每次都找到相同且不为零的元素数量。
  • 不稳定：能找到元素，但数量随加载而变化。
  • 未生效：在测试页面上未找到匹配项。
  • 错误：无法执行该规则。

检查包括当前基础域名的规则和不绑定域名的规则。BlockIt 保存普通域名绑定时不区分子域名：例如，在 e.mail.ru 创建的规则会保存为 mail.ru 的规则。但检查只针对启动诊断时打开的确切页面。因此，某个子域名或页面区域上有效的规则，在其他网址上可能显示“未生效”。请在创建规则时针对的页面上启动检查。

检查只统计匹配项，不判断元素用途。非零结果说明规则找到了内容，却不保证只找到了您想屏蔽的元素。请结合页面实际效果检查匹配数量。

问题排查 返回顶部

广告之外的内容也被屏蔽了

选择器范围过大时，不仅会找到广告，也会找到页面上的其他元素。

处理方法：

  • 按“管理规则”中的说明删除规则。
  • 在 HTML 树中向上或向下寻找更准确的容器，确保它只包含广告。
  • 添加规则前检查匹配数量。只有所有匹配项都应被屏蔽时，多个匹配才是合适的。
规则没有生效
  • 可能原因 1：选中的不是最外层元素。在 HTML 树中向上移动，复制父容器的选择器。
  • 可能原因 2：网站使用动态类名（混淆）。复制的选择器可能在刷新后失效。请在“创建规则的方法”中标记元素特征不稳定，并尝试建议的方法，例如 StableHTMLFinder 或规则构建器。
  • 可能原因 3：创建规则后页面结构发生变化。检查元素当前的 HTML 和匹配数量。如果网站重建了区块，请重新复制选择器或在构建器中完善规则。
  • 可能原因 4：规则为其他域名创建。检查它属于“此网站”还是“其他网站”。
选择器找不到任何元素
  • 检查选择器：打开开发者工具（F12），转到“元素” / “Elements”标签页，按 Ctrl + F（Mac 上按 Cmd + F），在搜索框中输入选择器。如果仍找不到元素，则选择器有误。
删除元素后页面布局变差
  • 解决方法：删除规则，并使用“隐藏”模式重新创建。这样会保留元素占用的空间，避免打乱布局。
选择器找到的元素太多

先检查数量，并弄清哪些元素被匹配。如果目标元素有稳定的类或属性，请将其加入选择器。若简单选择器不够精确，可使用规则构建器：它能考虑文本、类和属性数量、兄弟位置以及周围元素的关系。完善规则后，在当前页面和刷新后再次检查。

我看不懂页面的 HTML 结构

可以使用 StableHTMLFinder：它比较多次加载并生成稳定性地图。在地图中搜索目标元素，再检查其稳定特征和周围元素。

如果标记被严重混淆，网站可能向 VPN 连接提供不同的页面版本。情况允许时，可暂时关闭 VPN、刷新页面并重新分析。这并非对所有网站都有帮助，但可确认复杂标记是否与当前连接获得的页面版本有关。

仍然无法解决

尝试将 StableHTMLFinder 找到的稳定特征与 BlockIt 规则构建器结合，手动创建同时考虑元素及其周围结构的规则。

如果尝试多种方法后规则仍无效，或扩展程序出现错误，请通过 BlockIt 的反馈表单报告问题。尽可能附上页面网址、规则和截图。
