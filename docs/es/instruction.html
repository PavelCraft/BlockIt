¿Qué es BlockIt?

Los sitios con publicidad y los bloqueadores populares mantienen una carrera armamentística constante: los desarrolladores de sitios buscan eludir las listas públicas de filtros y los desarrolladores de bloqueadores las actualizan continuamente.

BlockIt adopta otro enfoque para bloquear anuncios y otros elementos no deseados. En vez de depender solo de listas compartidas, usted crea reglas para elementos concretos de los sitios que utiliza. Mientras no comparta esas reglas, el sitio desconoce en qué características se apoyan y le resulta más difícil inutilizarlas deliberadamente.

Características principales

  • Facilidad de uso: no necesita memorizar la sintaxis de los selectores CSS, XPath ni las reglas de BlockIt. A veces basta con copiar un selector de DevTools y pegarlo en la extensión.
  • Flexibilidad:
    • Usted decide si elimina un elemento o lo oculta
    • Usted decide qué elementos bloquear y cuáles conservar
    • Usted decide qué reglas conservar, desactivar o eliminar
    • Se admiten selectores CSS y expresiones XPath
    • Las reglas también se aplican dentro de iframes y Shadow DOM
  • Privacidad: todas las reglas se guardan localmente en el navegador y no se envían a ningún sitio.
  • Sintaxis de BlockIt: los casos complejos pueden usar una sintaxis que amplía los selectores CSS estándar. Consulte cuando lo necesite la documentación de la sintaxis de BlockIt.
  • Reglas agrupadas por sitio: las reglas se agrupan automáticamente para el sitio actual y para los demás sitios, lo que facilita su gestión.
  • Compartir ajustes: exporte sus reglas a un archivo para compartirlas con otros usuarios.
  • Varios idiomas: la extensión sigue el idioma del navegador. Admite ruso, inglés, francés, alemán, español, portugués, chino y japonés. Si su idioma no está disponible, la interfaz se muestra en inglés.
  • Código abierto: la extensión se desarrolla con licencia BSD-3-Clause. Puede colaborar, proponer mejoras y consultar el código en GitHub.

Consejos para elegir el elemento que se bloqueará

Antes de copiar un selector o HTML, determine exactamente qué elemento quiere bloquear.

  • Use el resaltado de DevTools. Pase sobre las filas HTML para resaltar los elementos correspondientes y ver qué zona se bloqueará.
  • Elija el elemento más exterior sin incluir nada adicional. Busque el contenedor más exterior que solo incluya el bloque deseado. Uno demasiado profundo puede dejar parte del anuncio visible; uno demasiado amplio puede ocultar contenido útil.
  • Vigile el número de elementos. BlockIt muestra las coincidencias al pegar una regla. Una suele ser más segura. Varias están bien si las ha revisado todas; 0 significa que no encontrará nada.

Si una regla bloquea demasiado o no bloquea nada, elimínela y elija otro elemento más arriba o abajo en el árbol HTML.

Modos de bloqueo

  • Eliminar: quita el elemento del HTML y libera su espacio. Funciona en la mayoría de los casos, pero a veces puede alterar el diseño.
  • Ocultar: vuelve invisible el elemento, pero conserva su espacio. Úselo si al eliminarlo la página se ve peor.

Primero encuentre el elemento en DevTools y examine su etiqueta, sus clases y sus atributos.

1Copiar un selector CSS de DevTools Seleccione para leer

Empiece aquí para comprobar rápidamente si un selector estándar puede bloquear el elemento. DevTools lo crea automáticamente: seleccione el elemento y elija «Copiar» / “Copy” → «Copiar selector» / “Copy selector”.

Pegue el selector en el campo principal de BlockIt, compruebe las coincidencias y añada la regla. Si deja de ser fiable tras recargar, use StableHTMLFinder o el constructor de reglas.

1
2Copiar XPath de DevTools Seleccione para leer

XPath describe una ruta hasta un elemento a través de la estructura de la página. Puede ayudar si las clases y otros atributos son inestables, pero la ruta no cambia. Elija «Copiar XPath» / “Copy XPath” en DevTools y pegue la expresión en BlockIt.

Revise la expresión copiada. Chrome puede construir XPath alrededor de un id. Si ese ID cambia, XPath también será inestable. Una ruta absoluta con números de posición dejará de funcionar si cambia la estructura HTML.

BlockIt evalúa XPath por separado en el documento principal y en cada iframe, por lo que un XPath copiado dentro de un iframe puede funcionar. Los navegadores no evalúan XPath a través de un límite de Shadow DOM. En ese caso, use el constructor o StableHTMLFinder para crear una regla basada en CSS o una regla ampliada de BlockIt.

StableHTMLFinder no bloquea elementos por sí mismo. Ayuda a elegir la base de una regla de BlockIt:

  • Selector CSS: la opción más sencilla si usa características estables y encuentra el número correcto de elementos.
  • Regla de BlockIt: úsela cuando una coincidencia precisa necesite sintaxis ampliada que CSS estándar no ofrece.

El constructor permite crear reglas precisas sin conocer CSS, XPath ni la sintaxis de BlockIt. Sirve para elementos estables e inestables: puede usar texto, número de atributos o clases, posición entre hermanos y elementos del entorno en vez de una clase concreta.

Copie el HTML del elemento en DevTools, abra el «Modo avanzado» de BlockIt, pegue el HTML en el campo correspondiente y pulse «Abrir constructor de reglas».

Tarjeta de elemento

Cada tarjeta describe un elemento HTML: etiqueta, número de atributos y condiciones basadas en atributos, texto y posición.

Árbol de relaciones

Los antepasados aparecen arriba, los descendientes debajo con sangría y los hermanos en el mismo nivel.

Características estables

Puede desactivar los valores insertados automáticamente. No use ID o clases cambiantes solo porque aparezcan en el HTML.

Comprobación

Compruebe las coincidencias de inmediato y luego use «Comprobar después de recargar» para verificar que el resultado siga estable.

Condiciones disponibles en una tarjeta

  • Etiqueta: indíquela o déjela vacía si no es importante.
  • Número de atributos: exactamente, como mínimo o como máximo la cantidad indicada.
  • Atributos: condiciones para nombres y valores; para class también puede indicar el número de clases.
  • Texto: texto propio del elemento o todo el texto interior; coincidencia exacta, prefijo, sufijo, fragmento o expresión regular.
  • Posición entre hermanos: lugar del elemento entre los hijos del mismo padre.

Elementos relacionados

Puede añadir un padre directo o cualquier antepasado al objetivo y a sus antepasados. El objetivo también puede tener un hijo, descendiente o hermano; los hermanos pueden tener sus propios descendientes. Los elementos relacionados disponen del interruptor «Puede faltar».

Posición entre hermanos es el lugar entre los hijos de un padre. Posición en los resultados de la regla es el lugar entre todos los elementos encontrados por la regla completa. Son condiciones distintas.

Vista previa y comprobación

Lea la descripción en lenguaje natural de «Vista previa de la regla». Ayuda a detectar atributos, condiciones de texto o relaciones incluidos por error. Después compruebe las coincidencias en la página actual y tras recargar.

Ejemplo: configurar una regla para varios elementos

  1. Active «Posición entre hermanos» e indique las posiciones necesarias: 2, 3 y 5 en este ejemplo.
  2. Mantenga la coincidencia exacta para el nombre del atributo class.
  3. Quite la parte poco fiable del valor de clase y cambie «valor: exactamente» por «valor: contiene».
  4. Desactive «Número de clases» si esa cifra no es importante y puede cambiar.
  5. Lea «Vista previa de la regla» y compruebe que todas las condiciones sean necesarias.
  6. Cierre DevTools en la página objetivo y pulse «Comprobar después de recargar». Algunos sitios cargan contenido distinto cuando DevTools está abierto.
  7. Compruebe que el número de coincidencias no cambie tras recargar. Eso indica que la regla es estable.
  8. Pulse «Crear regla».

Resumen de selectores CSS Volver arriba

¿Qué son los selectores?

Los selectores encuentran un elemento de una página por sus propiedades: etiqueta, clase, identificador, atributos o posición en la estructura HTML.

En los estilos CSS, los selectores aplican formato. En BlockIt se usan solo para encontrar elementos. No definimos colores, fuentes ni espacios: simplemente encontramos un elemento para bloquearlo.

Estos ejemplos le ayudarán a leer y modificar ligeramente selectores CSS normales.

Cómo comprobar un selector

  1. Abra la pestaña «Elementos» / “Elements” de DevTools.
  2. Pulse Ctrl + F o Cmd + F en Mac.
  3. Pegue el selector en el campo de búsqueda.
  4. DevTools resalta todas las coincidencias y muestra su número, por ejemplo 1 of 3.
1

Tipos de selectores

Selector universal (*)

Encuentra todos los elementos de la página. Úselo con cuidado: devuelve todo el HTML.

Selector: *

Qué encuentra: todos los elementos sin excepción.

Selector por etiqueta

Encuentra todos los elementos con la etiqueta HTML indicada.

Selectores: h1, p, button, div

Qué encuentran:

  • h1 — todos los encabezados de primer nivel;
  • p — todos los párrafos;
  • button — todos los botones;
  • div — todos los contenedores <div>.

Selector por clase (.class)

Encuentra los elementos con la clase indicada en class. Escriba varias clases seguidas, sin espacios.

Selectores: .card, .card__title, .card.featured

Qué encuentran:

  • .card — todos los elementos con la clase card;
  • .card__title — todos los elementos con la clase card__title;
  • .card.featured — elementos que tienen a la vez las clases card y featured.

El elemento puede tener otras clases: class="card featured compact" también coincide con .card.featured. Para hacer coincidir toda la cadena exactamente puede usar [class="card featured"], pero depende del orden y no admite clases adicionales.

Selector por identificador (#id)

Encuentra un elemento con un id único. La página debería contener uno solo con ese ID.

Selectores: #salad-cat, #confused-cat, #bread-cat

Qué encuentran:

  • #salad-cat: el elemento con id="salad-cat";
  • #confused-cat: el elemento con id="confused-cat";
  • #bread-cat: el elemento con id="bread-cat".

Selector por atributo ([atributo="valor"])

Puede comprobar un atributo por un valor exacto o solo por su presencia. Escriba varias condiciones seguidas.

Selectores: [data-type], [data-type="description"], [data-type="description"][aria-label="Card"], [class~="card"], [class="card featured"]

Qué encuentran:

  • [data-type]: elementos que tienen data-type con cualquier valor;
  • [data-type="description"]: elementos cuyo valor data-type es exactamente description;
  • [data-type="description"][aria-label="Card"]: elementos donde coinciden ambos atributos;
  • [class~="card"]: elementos cuya lista de clases contiene la clase independiente card;
  • [class="card featured"]: elementos cuyo atributo class completo coincide exactamente con la cadena indicada.
Formas de comparar un valor
[href^="https://"]
el valor empieza por https://
[src$=".png"]
el valor termina en .png
[class*="advert"]
el valor contiene advert en cualquier posición
[class~="card"]
la lista de palabras separadas por espacios contiene la palabra card
[lang|="en"]
el valor es en o empieza por en-, por ejemplo en-US
[aria-label*="advertisement" i]
el valor contiene «advertisement» sin distinguir mayúsculas y minúsculas

Un selector solo comprueba los atributos que enumera y no prohíbe otros. Por ejemplo, [data-type="description"][aria-label="Card"] encuentra <div data-type="description" aria-label="Card" title="Details">: el atributo adicional title no impide la coincidencia. Un selector CSS normal no puede exigir que no haya otros atributos.

Selectores combinados

Puede combinar etiqueta, clase, ID y condiciones de atributos sin espacios para que todas se apliquen al mismo elemento.

Selectores: h2.card__title, div.card.featured, div[data-type="description"], article.card[data-type="advertisement"][aria-label="Advertisement"]

Qué encuentran:

  • h2.card__title: un <h2> con la clase card__title;
  • div.card.featured: un <div> con las clases card y featured; se permiten otras;
  • div[data-type="description"]: un <div> con el atributo indicado; se permiten otros;
  • article.card[data-type="advertisement"][aria-label="Advertisement"]: un <article> con clase card cuyos atributos son exactamente data-type="advertisement" y aria-label="Advertisement".

Selector de descendiente (espacio)

Encuentra elementos situados dentro de otro a cualquier nivel.

Selector: .card .btn

Qué encuentra: todos los elementos con clase btn dentro de uno con clase card.

Selector de hijo (>)

Encuentra elementos que son hijos directos de otro. Solo busca un nivel hacia abajo.

Selector: .card__body > .card__title

Qué encuentra: elementos con clase card__title que son hijos directos de uno con clase card__body.

Selector de hermano adyacente (+)

Encuentra el hermano siguiente de otro elemento en el mismo nivel.

Selector: #confused-cat + .card__description

Qué encuentra: un <p> situado inmediatamente después del elemento con id="confused-cat".

Pseudoclase de posición

Selecciona elementos por su posición entre hermanos.

Selector: .card__actions :nth-child(2)

Qué encuentra: el segundo hijo dentro de un elemento con clase card__actions.

Los selectores CSS normales tienen limitaciones. No describen el número de atributos o clases sin enumerarlos, el texto propio del elemento, texto arbitrario en su interior, expresiones regulares ni patrones de nombres de atributos. Por ejemplo, [data-*] no es CSS estándar. Para estos casos se usan reglas de BlockIt, que amplían CSS con construcciones como [data-*], :attr-name(/^data-/) y otras condiciones. Consulte la documentación de la sintaxis de BlockIt.

¿Qué son iframe y Shadow DOM? Volver arriba

iframe es una página web independiente incrustada en otra. Su contenido está en su propio documento, por lo que una búsqueda normal desde la página principal no puede entrar en él.

Aspecto de un iframe en HTML 
<main>
  <h1>Página principal</h1>
  <iframe src="advertisement.html"></iframe>
</main>

El marcado de advertisement.html se carga como documento independiente dentro del <iframe>.

Shadow DOM es un árbol interno aislado de un componente. El sitio lo usa para separar su marcado del resto de la página; una raíz cerrada también lo oculta a los scripts normales.

Aspecto de Shadow DOM en DevTools 
<video-player>
  #shadow-root (open)
    <button class="play">Reproducir</button>
</video-player>

El botón está dentro de la raíz de sombra de <video-player>, no en el árbol normal de la página principal.

Esto crea límites de búsqueda: una regla debe ejecutarse en el documento principal y dentro de cada iframe y raíz de sombra accesible. No todos los bloqueadores lo hacen. BlockIt aplica selectores CSS y reglas ampliadas dentro de iframe y Shadow DOM; XPath solo funciona en documentos y no atraviesa Shadow DOM.

Gestión de reglas Volver arriba

Las reglas creadas aparecen en la lista del sitio actual o en la de reglas sin dominio. Las reglas del constructor se pueden editar o eliminar; las desactivadas permanecen con su marca correspondiente.

Desactivación y eliminación

¿Cómo desactivo una regla?

Busque la regla en «Reglas activas» y pulse «Desactivar». Seguirá en su sitio con la marca «Desactivada», pero ya no se aplicará. Si ya quitó un elemento de la página abierta, recárguela.

¿Cómo elimino una regla?

Busque la regla en «Reglas activas» y pulse «Eliminar». Para recuperar un elemento ya eliminado, recargue la página con F5 o el botón de actualización.

Exportación e importación

La exportación guarda las reglas en un archivo. La importación añade reglas desde él o sustituye la lista actual. Sirve para transferir ajustes entre dispositivos.

1

Comprobación de reglas

Abra la página donde quiera comprobarlas y después BlockIt. En el encabezado «Para este sitio: <dominio>», pulse «Comprobar reglas».

La comprobación indica si las reglas guardadas encuentran elementos. Puede medir una vez o activar «Comprobar estabilidad» y elegir varias recargas. BlockIt deja de aplicar las reglas temporalmente, recarga la página y muestra las coincidencias de cada regla en cada carga.

  • Funciona: siempre encuentra el mismo número de elementos, distinto de cero.
  • Inestable: encuentra elementos, pero su número cambia entre cargas.
  • No funcionó: no se encontraron coincidencias en la página comprobada.
  • Error: no se pudo ejecutar la regla.

Se incluyen las reglas del dominio base actual y las que no tienen dominio. BlockIt no separa subdominios al guardar una vinculación normal: una regla creada en e.mail.ru se guarda para mail.ru. Sin embargo, se comprueba la página exacta desde la que abrió el diagnóstico. Por eso una regla válida para un subdominio puede figurar como «No funcionó» en otro. Para un resultado fiable, abra la página para la que creó la regla.

La comprobación mide coincidencias, no la finalidad de los elementos. Un resultado distinto de cero significa que encontró algo, pero no garantiza que sean solo los elementos que quería bloquear. Compare el número y el resultado en la página.

Solución de problemas Volver arriba

Se bloqueó algo más junto con la publicidad

Ocurre cuando el selector es demasiado amplio y encuentra otros elementos además del anuncio.

Qué hacer:

  • Elimine la regla como se explica en «Gestión de reglas».
  • Elija un elemento más preciso: suba o baje por el árbol HTML hasta encontrar un contenedor que incluya solo el anuncio.
  • Compruebe las coincidencias antes de añadir la regla. Varias solo son aceptables si debe bloquearlas todas.
La regla creada no funcionó
  • Posible causa 1: no eligió el elemento más exterior. Suba en el árbol HTML y copie el selector del contenedor padre.
  • Posible causa 2: el sitio usa clases dinámicas (ofuscación). El selector copiado puede dejar de funcionar al recargar. En «Formas de crear una regla», marque las características como inestables y use un método sugerido, como StableHTMLFinder o el constructor.
  • Posible causa 3: la página cambió de estructura después de crear la regla. Compruebe el HTML actual y las coincidencias. Si el sitio reconstruyó el bloque, vuelva a copiar el selector o refine la regla en el constructor.
  • Posible causa 4: la regla se creó para otro dominio. Compruebe si está en «Para este sitio» o «Para otros sitios».
El selector no encuentra ningún elemento
  • Compruebe el selector: abra DevTools (F12), vaya a «Elementos» / “Elements”, pulse Ctrl + F (Cmd + F en Mac) e introduzca el selector. Si no encuentra nada, el selector es incorrecto.
El diseño se rompió al eliminar un elemento y ahora se ve peor
  • Solución: elimine la regla y créela otra vez con «Ocultar». Así conserva el espacio y no altera el diseño.
El selector encuentra demasiados elementos

Compruebe primero el número y qué elementos aparecen. Si el elemento tiene una clase o atributo estable, añádalo al selector. Si no basta, use el constructor: puede considerar texto, número de clases y atributos, posición entre hermanos y relaciones con el entorno. Vuelva a comprobar la regla en la página y tras recargar.

No logro entender la estructura HTML de la página

Use StableHTMLFinder: compara varias cargas y crea un mapa de estabilidad. Busque el elemento y examine sus características estables y su entorno.

Si el marcado parece muy ofuscado, el sitio puede servir otra variante a conexiones VPN. Si es posible, desactive temporalmente la VPN, recargue y repita el análisis. No ayuda en todos los sitios, pero permite comprobar si la complejidad depende de la variante recibida.

Nada ayuda

Combine las características estables de StableHTMLFinder con el constructor de BlockIt. Así puede crear manualmente una regla que use el elemento y su entorno.

Si ha probado varios métodos y la regla sigue sin funcionar o la extensión da errores, envíe un informe mediante el formulario de comentarios. Incluya la URL, la regla y, si es posible, capturas.
