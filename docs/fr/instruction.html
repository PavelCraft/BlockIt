Guide d’utilisation de BlockIt

Créez des règles pour bloquer les éléments indésirables, du simple sélecteur CSS à une règle précise fondée sur la structure de la page.

Qu’est-ce que BlockIt ?

Les sites publicitaires et les bloqueurs populaires sont engagés dans une course permanente : les développeurs de sites cherchent à contourner les listes publiques de filtres, tandis que les développeurs de bloqueurs les mettent sans cesse à jour.

BlockIt adopte une autre approche pour bloquer les publicités et les éléments indésirables. Au lieu de dépendre uniquement de listes partagées, vous créez des règles pour des éléments précis des sites que vous utilisez. Tant que vous ne les partagez pas, le site ignore les caractéristiques sur lesquelles elles reposent et peut plus difficilement les neutraliser volontairement.

Fonctionnalités principales

  • Simplicité : vous n’avez pas à mémoriser la syntaxe CSS, XPath ou BlockIt. Il suffit parfois de copier un sélecteur depuis DevTools et de le coller dans l’extension.
  • Souplesse :
    • Vous choisissez de supprimer ou de masquer un élément
    • Vous choisissez les éléments à bloquer ou à conserver
    • Vous choisissez les règles à conserver, désactiver ou supprimer
    • Les sélecteurs CSS et les expressions XPath sont pris en charge
    • Les règles s’appliquent aussi dans les iframes et le Shadow DOM
  • Confidentialité : toutes les règles sont stockées localement dans votre navigateur et ne sont envoyées nulle part.
  • Syntaxe BlockIt : les cas complexes peuvent utiliser une syntaxe qui étend les sélecteurs CSS standard. Consultez au besoin la documentation de la syntaxe BlockIt.
  • Regroupement par site : les règles sont automatiquement regroupées pour le site actuel et les autres sites.
  • Partage des réglages : exportez vos règles dans un fichier pour les partager.
  • Plusieurs langues : l’extension suit la langue du navigateur. Le russe, l’anglais, le français, l’allemand, l’espagnol, le portugais, le chinois et le japonais sont pris en charge. À défaut, l’interface est en anglais.
  • Code source ouvert : l’extension est développée sous licence BSD-3-Clause. Vous pouvez contribuer, proposer des améliorations et consulter le code sur GitHub.

Conseils pour choisir l’élément à bloquer

Avant de copier un sélecteur ou du HTML, déterminez précisément l’élément à bloquer.

  • Utilisez le surlignage de DevTools. Survolez les lignes HTML pour voir les éléments correspondants et la zone qui sera bloquée.
  • Choisissez l’élément le plus extérieur sans rien inclure de plus. Un élément trop profond peut laisser une partie de la publicité visible ; un élément trop large peut masquer du contenu utile.
  • Surveillez le nombre d’éléments. BlockIt affiche les correspondances après le collage. Une est souvent plus sûre. Plusieurs conviennent si vous les avez toutes vérifiées ; 0 signifie que rien ne sera trouvé.

Si la règle bloque trop ou rien du tout, supprimez-la et choisissez un autre élément plus haut ou plus bas dans l’arbre HTML.

Modes de blocage

  • Supprimer : retire l’élément du HTML et libère son espace. Cela peut parfois modifier la mise en page.
  • Masquer : rend l’élément invisible tout en conservant son espace. Utilisez ce mode si la suppression dégrade la page.

2Copier le XPath depuis DevTools Sélectionnez pour lire

XPath décrit un chemin jusqu’à l’élément dans la structure. Il peut aider quand les attributs sont instables mais que le chemin reste inchangé. Choisissez « Copier le XPath » / “Copy XPath”, puis collez l’expression dans BlockIt.

Examinez l’expression copiée. Chrome peut construire XPath autour d’un id. Si cet ID change, XPath est lui aussi instable. Un chemin absolu numéroté casse lorsque la structure HTML change.

BlockIt évalue XPath séparément dans le document principal et dans chaque iframe ; un XPath copié dans un iframe peut donc fonctionner. Les navigateurs n’évaluent pas XPath au-delà d’une limite du Shadow DOM. Utilisez alors le constructeur ou StableHTMLFinder pour créer une règle CSS ou BlockIt étendue.

Fiche d’élément

Chaque fiche décrit un élément HTML : balise, nombre d’attributs et conditions sur les attributs, le texte et la position.

Arbre des relations

Les ancêtres sont au-dessus, les descendants en dessous avec un retrait et les frères au même niveau.

Caractéristiques stables

Vous pouvez désactiver les valeurs ajoutées automatiquement. N’utilisez pas des ID ou classes changeants simplement parce qu’ils figurent dans le HTML.

Vérification

Vérifiez immédiatement le nombre de correspondances, puis utilisez « Vérifier après actualisation » pour confirmer sa stabilité.

Conditions disponibles dans une fiche

  • Balise : indiquez-la ou laissez vide si elle importe peu.
  • Nombre d’attributs : exactement, au moins ou au plus le nombre indiqué.
  • Attributs : conditions sur les noms et valeurs ; pour class, vous pouvez aussi fixer le nombre de classes.
  • Texte : texte propre ou tout le texte intérieur ; correspondance exacte, préfixe, suffixe, fragment ou expression régulière.
  • Position parmi les frères : place parmi les enfants du même parent.

Éléments liés

Vous pouvez ajouter un parent direct ou un ancêtre à la cible et à ses ancêtres. La cible peut aussi avoir un enfant, un descendant ou un frère. Les éléments liés disposent du bouton « Peut être absent ».

Position parmi les frères désigne la place parmi les enfants d’un même parent. Position dans les résultats désigne la place parmi tous les éléments trouvés par la règle complète. Ce sont deux conditions différentes.

Aperçu et vérification

Lisez la description de « Aperçu de la règle ». Elle révèle les attributs, conditions de texte ou relations ajoutés par erreur. Vérifiez ensuite les correspondances sur la page actuelle et après actualisation.

Exemple : une règle pour plusieurs éléments

  1. Activez « Position parmi les frères » et saisissez 2, 3 et 5 dans cet exemple.
  2. Conservez la correspondance exacte du nom d’attribut class.
  3. Retirez la partie peu fiable de la valeur de classe et remplacez « valeur : exactement » par « valeur : contient ».
  4. Désactivez « Nombre de classes » si ce nombre peut changer.
  5. Lisez « Aperçu de la règle » et vérifiez que chaque condition est nécessaire.
  6. Fermez DevTools sur la page cible et cliquez sur « Vérifier après actualisation ». Certains sites chargent un contenu différent lorsque DevTools est ouvert.
  7. Vérifiez que le nombre de correspondances ne change pas après actualisation : la règle est alors stable.
  8. Cliquez sur « Créer la règle ».

Aide-mémoire des sélecteurs CSS Retour en haut

Que sont les sélecteurs ?

Les sélecteurs trouvent un élément selon ses propriétés : balise, classe, identifiant, attributs ou position dans la structure HTML.

Dans les styles CSS, ils appliquent une mise en forme. Dans BlockIt, ils servent uniquement à trouver des éléments afin de les bloquer.

Ces exemples vous aideront à lire et modifier légèrement les sélecteurs CSS courants.

Vérifier un sélecteur

  1. Ouvrez l’onglet « Éléments » / “Elements” de DevTools.
  2. Appuyez sur Ctrl + F, ou Cmd + F sur Mac.
  3. Collez le sélecteur dans la recherche.
  4. DevTools surligne les correspondances et en indique le nombre, par exemple 1 of 3.
1

Types de sélecteurs

Sélecteur universel (*)

Trouve tous les éléments. Utilisez-le avec prudence : il renvoie tout le HTML.

Sélecteur : *

Ce qu’il trouve : tous les éléments sans exception.

Sélecteur de balise

Trouve tous les éléments portant la balise HTML indiquée.

Sélecteurs : h1, p, button, div

Ce qu’ils trouvent :

  • h1 — tous les titres de premier niveau ;
  • p — tous les paragraphes ;
  • button — tous les boutons ;
  • div — tous les conteneurs <div>.

Sélecteur de classe (.class)

Trouve les éléments ayant la classe indiquée. Écrivez plusieurs classes à la suite, sans espace.

Sélecteurs : .card, .card__title, .card.featured

Ce qu’ils trouvent :

  • .card — tous les éléments de classe card ;
  • .card__title — tous les éléments de classe card__title ;
  • .card.featured — les éléments ayant les classes card et featured.

L’élément peut avoir d’autres classes : class="card featured compact" correspond aussi à .card.featured. [class="card featured"] exige la chaîne complète, dans cet ordre et sans classe supplémentaire.

Sélecteur d’identifiant (#id)

Trouve l’élément portant l’id unique indiqué.

Sélecteurs : #salad-cat, #confused-cat, #bread-cat

Ce qu’ils trouvent :

  • #salad-cat — l’élément avec id="salad-cat" ;
  • #confused-cat — l’élément avec id="confused-cat" ;
  • #bread-cat — l’élément avec id="bread-cat".

Sélecteur d’attribut ([attribut="valeur"])

Vous pouvez vérifier une valeur exacte ou la présence d’un attribut. Écrivez plusieurs conditions à la suite.

Sélecteurs : [data-type], [data-type="description"], [data-type="description"][aria-label="Card"], [class~="card"], [class="card featured"]

Ce qu’ils trouvent :

  • [data-type] — les éléments possédant data-type, quelle que soit sa valeur ;
  • [data-type="description"] — les éléments dont data-type vaut exactement description ;
  • [data-type="description"][aria-label="Card"] — les éléments où les deux attributs correspondent ;
  • [class~="card"] — les éléments dont la liste de classes contient la classe distincte card ;
  • [class="card featured"] — les éléments dont l’attribut class complet correspond exactement.
Façons de comparer une valeur
[href^="https://"]
la valeur commence par https://
[src$=".png"]
la valeur se termine par .png
[class*="advert"]
la valeur contient advert n’importe où
[class~="card"]
la liste de mots séparés par des espaces contient le mot card
[lang|="en"]
la valeur vaut en ou commence par en-, par exemple en-US
[aria-label*="advertisement" i]
la valeur contient « advertisement », sans tenir compte de la casse

Un sélecteur ne vérifie que les attributs indiqués et n’interdit pas les autres. Ainsi, [data-type="description"][aria-label="Card"] trouve aussi un élément ayant un attribut title supplémentaire. Le CSS standard ne peut pas exiger l’absence de tout autre attribut.

Sélecteurs combinés

Balise, classe, ID et conditions d’attribut peuvent être combinés sans espace pour le même élément.

Sélecteurs : h2.card__title, div.card.featured, div[data-type="description"], article.card[data-type="advertisement"][aria-label="Advertisement"]

Ce qu’ils trouvent :

  • h2.card__title — un <h2> de classe card__title ;
  • div.card.featured — un <div> avec les classes card et featured ; d’autres sont autorisées ;
  • div[data-type="description"] — un <div> avec l’attribut indiqué ; d’autres sont autorisés ;
  • article.card[data-type="advertisement"][aria-label="Advertisement"] — un <article> de classe card dont les deux valeurs d’attribut correspondent exactement à data-type="advertisement" et aria-label="Advertisement".

Sélecteur de descendant (espace)

Trouve les éléments situés dans un autre, à n’importe quel niveau.

Sélecteur : .card .btn

Ce qu’il trouve : tous les éléments de classe btn dans un élément de classe card.

Sélecteur d’enfant (>)

Trouve les enfants directs d’un autre élément.

Sélecteur : .card__body > .card__title

Ce qu’il trouve : les éléments de classe card__title enfants directs d’un élément de classe card__body.

Sélecteur de frère adjacent (+)

Trouve le frère suivant au même niveau.

Sélecteur : #confused-cat + .card__description

Ce qu’il trouve : un <p> suivant immédiatement l’élément id="confused-cat".

Pseudo-classe de position

Sélectionne les éléments selon leur position parmi leurs frères.

Sélecteur : .card__actions :nth-child(2)

Ce qu’il trouve : le deuxième enfant d’un élément de classe card__actions.

Les sélecteurs CSS standard ont des limites. Ils ne décrivent pas le nombre d’attributs ou de classes sans les énumérer, le texte propre ou interne, les expressions régulières ni les motifs de noms d’attributs. [data-*] n’est par exemple pas du CSS standard. Les règles BlockIt étendent CSS avec [data-*], :attr-name(/^data-/) et d’autres conditions. Consulter la documentation de la syntaxe BlockIt.

Que sont iframe et Shadow DOM ? Retour en haut

iframe est une page web distincte intégrée dans une autre. Son contenu appartient à son propre document ; une recherche ordinaire depuis la page parente ne peut donc pas y entrer directement.

Aspect d’un iframe en HTML 
<main>
  <h1>Page principale</h1>
  <iframe src="advertisement.html"></iframe>
</main>

Le balisage de advertisement.html est chargé comme document distinct dans l’<iframe>.

Shadow DOM est l’arbre interne isolé d’un composant. Le site sépare ainsi son balisage du reste de la page ; une racine fermée le masque aussi aux scripts ordinaires.

Aspect du Shadow DOM dans DevTools 
<video-player>
  #shadow-root (open)
    <button class="play">Play</button>
</video-player>

Le bouton se trouve dans la racine d’ombre de <video-player>, pas dans l’arbre ordinaire de la page.

Ces structures créent des limites de recherche : la règle doit s’exécuter dans le document principal, chaque iframe et chaque racine d’ombre accessible. Tous les bloqueurs ne le font pas. BlockIt applique CSS et ses règles étendues dans iframe et Shadow DOM ; XPath ne traverse toutefois pas une limite Shadow DOM.

Gestion des règles Retour en haut

Les règles créées figurent dans la liste du site actuel ou dans celle sans domaine. Les règles du constructeur peuvent être modifiées ou supprimées ; les règles désactivées restent marquées dans la liste.

Désactivation et suppression

Comment désactiver une règle ?

Repérez-la dans « Règles actives » et cliquez sur « Désactiver ». Elle reste marquée « Désactivée », mais n’est plus appliquée. Actualisez la page pour restaurer un élément déjà supprimé.

Comment supprimer une règle ?

Repérez-la dans « Règles actives » et cliquez sur « Supprimer ». Rechargez ensuite la page avec F5 ou le bouton d’actualisation.

Exportation et importation

L’exportation enregistre les règles dans un fichier. L’importation les ajoute ou remplace la liste actuelle. Cela permet de transférer les réglages entre appareils.

1

Vérification des règles

Ouvrez la page à vérifier puis BlockIt. Dans « Pour ce site : <domaine> », cliquez sur « Vérifier les règles ».

La vérification indique si les règles trouvent des éléments. Vous pouvez mesurer une fois ou activer « Vérifier la stabilité » et choisir plusieurs rechargements. BlockIt suspend alors temporairement les règles et affiche leurs correspondances à chaque chargement.

  • Fonctionne : même nombre non nul à chaque vérification.
  • Instable : le nombre change entre les chargements.
  • N’a pas fonctionné : aucune correspondance.
  • Erreur : la règle n’a pas pu être exécutée.

La vérification inclut les règles du domaine de base et celles sans domaine. BlockIt ne sépare pas les sous-domaines : une règle créée sur e.mail.ru est enregistrée pour mail.ru. En revanche, seule la page exacte depuis laquelle le diagnostic est ouvert est contrôlée. Lancez donc la vérification depuis la page pour laquelle la règle a été créée.

La vérification mesure les correspondances, pas leur fonction. Un résultat non nul ne garantit pas que seuls les éléments voulus ont été trouvés. Comparez le nombre et le résultat sur la page.

Résolution des problèmes Retour en haut

Autre chose a été bloqué avec la publicité

Cela arrive lorsque le sélecteur est trop large et trouve aussi d’autres éléments.

Que faire :

  • Supprimez la règle comme indiqué dans « Gestion des règles ».
  • Choisissez un élément plus précis dans l’arbre HTML, contenant uniquement la publicité.
  • Vérifiez les correspondances avant l’ajout. Plusieurs ne conviennent que si chacune doit être bloquée.
La règle n’a pas fonctionné
  • Cause possible 1 : l’élément choisi n’est pas le plus extérieur. Remontez dans l’arbre HTML et copiez le sélecteur du conteneur parent.
  • Cause possible 2 : le site utilise des classes dynamiques (obfuscation). Le sélecteur peut cesser de fonctionner après actualisation. Dans « Façons de créer une règle », indiquez que les caractéristiques sont instables et utilisez StableHTMLFinder ou le constructeur.
  • Cause possible 3 : la page a changé de structure après la création de la règle. Vérifiez le HTML actuel et les correspondances. Si le bloc a changé, recopiez le sélecteur ou affinez la règle.
  • Cause possible 4 : la règle a été créée pour un autre domaine. Vérifiez si elle figure dans « Pour ce site » ou « Pour les autres sites ».
Le sélecteur ne trouve aucun élément
  • Vérifiez le sélecteur : ouvrez DevTools (F12), allez dans « Éléments » / “Elements”, appuyez sur Ctrl + F (Cmd + F sur Mac) et saisissez le sélecteur. Si rien n’est trouvé, il est incorrect.
La mise en page s’est dégradée après la suppression
  • Solution : supprimez la règle et recréez-la avec « Masquer ». L’espace est conservé et la mise en page reste intacte.
Le sélecteur trouve trop d’éléments

Vérifiez d’abord le nombre et les éléments trouvés. Ajoutez une classe ou un attribut stable au sélecteur. Si cela ne suffit pas, le constructeur peut prendre en compte le texte, le nombre de classes et d’attributs, la position parmi les frères et les relations avec l’environnement. Revérifiez avant et après actualisation.

Je ne parviens pas à comprendre la structure HTML

Utilisez StableHTMLFinder : il compare plusieurs chargements et crée une carte de stabilité. Trouvez l’élément, puis examinez ses caractéristiques stables et son environnement.

Si le balisage est très obscurci, le site peut fournir une autre variante aux connexions VPN. Si possible, désactivez temporairement le VPN, rechargez et recommencez l’analyse.

Rien ne fonctionne

Combinez les caractéristiques stables trouvées par StableHTMLFinder avec le constructeur BlockIt pour tenir compte de l’élément et de son environnement.

Si la règle échoue toujours ou que l’extension produit des erreurs, envoyez un rapport via le formulaire de retour, avec l’URL, la règle et si possible des captures.
