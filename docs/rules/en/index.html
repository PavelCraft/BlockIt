BlockIt Rule Syntax

Syntax version 1

BlockIt rules extend CSS selectors with conditions that standard CSS cannot express reliably. A rule is still selector-like: begin with a CSS selector, then append BlockIt pseudo-classes.

div.card:attr-count(=2):has(> span:own-text("Advertisement"))

CSS foundation

Tag, ID, class and attribute selectors, selector lists and the standard combinators are supported:

div.notice
#banner
section[data-kind="ad"]
main > section
.anchor + .target
.anchor ~ .target
article, aside

Native CSS pseudo-classes supported by the browser may be used. BlockIt extensions can be nested in :has(), :is(), :where() and :not().

Values and regular expressions

Text values should normally be JSON-style quoted strings. Pattern-oriented pseudo-classes accept JavaScript regular expressions such as /^data-[a-z]+$/i. Positions and result numbers are one-based.

Attributes and classes

SyntaxMeaning
:attr-count(=3)Exactly three attributes. Operators: =, <, <=, >, >=. :attribute-count() is an alias.
:class-count(>=2)Number of class tokens.
:attr-name(/^data-/)An attribute name matches the regular expression.
:attr(/^data-/, /^ad-/)An attribute name and its value match the two regular expressions.
[data-*]An attribute whose name starts with data- exists. Operators may also be used.
:class-name(/^card-/)At least one class token matches the regular expression.
:attrs(["id", /^data-/])All listed exact names or name patterns exist.
:style-property("--adaptive-width")The inline style contains this CSS property; its value is ignored.

Text and HTML

SyntaxMeaning
:text("Advertisement")Exact normalized descendant text.
:own-text("Advertisement")Exact normalized direct text nodes only.
:text-starts(), :text-ends(), :text-contains(), :text-matches()Prefix, suffix, substring or regular-expression match against descendant text.
:own-text-starts(), :own-text-ends(), :own-text-contains(), :own-text-matches()The same modes for direct text nodes.
:html(/pattern/)The element's serialized HTML matches a regular expression.

Structure and relationships

SyntaxMeaning
:has(selector)A matching descendant or relative selector exists.
:within(selector)A matching ancestor exists; Shadow DOM hosts may be crossed.
:near(selector)A matching sibling exists in either direction at any distance.
:sibling-distance(previous, 2, selector)The second previous sibling matches.
:sibling-distance(next, 3, selector)The third next sibling matches.
:children(selector, >=2)The number of matching direct children satisfies the count.
:sibling-position(2)The element is the second child of its parent.
:matches-position(2)Keep the second result of the complete rule. Multiple positions may be separated by commas or spaces.

Runtime and accessibility conditions

SyntaxMeaning
:visible(...)Checks visibility in the live page.
:size(...)Checks rendered dimensions.
:style(...)Checks computed style.
:property(...)Checks a JavaScript DOM property.
:accessible(...)Checks accessibility-related properties.

These conditions depend on live browser state and may be unavailable when a saved DOM snapshot is searched.

Frames and Shadow DOM

SyntaxMeaning
:in-frame(...)Limits matching to frame content.
:in-shadow(...)Limits matching to Shadow DOM.
:frame-has(selector)An iframe document contains a match.
:has-frame(...)The element contains a frame satisfying the condition.

Cross-origin frames and closed Shadow Roots are subject to browser and extension permission limits.

Examples

div[class]:text-contains("Hide ads"):near(div.new-menu)
div.target:sibling-distance(previous, 2, div.new-menu)
div:style-property("--rc-adaptive-width")
section:has(> div:attr-count(=2) > span:own-text("Advertisement"))
div:attr-count(=1):class-count(=2):matches-position(2)

Compatibility

Saved rules will continue to work after BlockIt updates. New capabilities may be added without changing the meaning of existing syntax.
