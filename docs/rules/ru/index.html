Синтаксис правил BlockIt

Версия синтаксиса 1

Правила BlockIt расширяют CSS-селекторы условиями, которые невозможно или неудобно надёжно выразить обычным CSS. Правило остаётся похожим на селектор: сначала указывается CSS-часть, затем псевдоклассы BlockIt.

div.card:attr-count(=2):has(> span:own-text("Реклама"))

Версия сохраняется внутри записи правила в поле syntaxVersion. Добавлять префикс версии в текст правила не нужно. Старые правила без версии считаются правилами версии 1.

Основа CSS

Поддерживаются теги, идентификаторы, классы, атрибуты, списки селекторов и стандартные комбинаторы:

div.notice
#banner
section[data-kind="ad"]
main > section
.anchor + .target
.anchor ~ .target
article, aside

Можно использовать нативные псевдоклассы CSS, которые поддерживает браузер. Расширения BlockIt могут находиться внутри :has(), :is(), :where() и :not().

Значения и регулярные выражения

Текстовые значения рекомендуется записывать как строки JSON. Псевдоклассы для шаблонов принимают регулярные выражения JavaScript, например /^data-[a-z]+$/i. Нумерация позиций и результатов начинается с единицы.

Атрибуты и классы

СинтаксисЗначение
:attr-count(=3)Ровно три атрибута. Операторы: =, <, <=, >, >=. :attribute-count() — синоним.
:class-count(>=2)Количество отдельных классов.
:attr-name(/^data-/)Имя хотя бы одного атрибута соответствует регулярному выражению.
:attr(/^data-/, /^ad-/)Имя и значение одного атрибута соответствуют двум выражениям.
[data-*]Существует атрибут, имя которого начинается с data-. Можно добавить оператор значения.
:class-name(/^card-/)Хотя бы один класс соответствует выражению.
:attrs(["id", /^data-/])Существуют все перечисленные точные имена или шаблоны имён.
:style-property("--adaptive-width")В inline-атрибуте style существует указанное CSS-свойство; значение игнорируется.

Текст и HTML

СинтаксисЗначение
:text("Реклама")Точное совпадение нормализованного текста элемента и потомков.
:own-text("Реклама")Точное совпадение только собственного текста.
:text-starts(), :text-ends(), :text-contains(), :text-matches()Начало, конец, подстрока или регулярное выражение для всего текста.
:own-text-starts(), :own-text-ends(), :own-text-contains(), :own-text-matches()Те же режимы только для собственных текстовых узлов.
:html(/шаблон/)Сериализованный HTML элемента соответствует выражению.

Структура и связи

СинтаксисЗначение
:has(селектор)Есть подходящий потомок или элемент относительного селектора.
:within(селектор)Есть подходящий предок; возможен переход через host Shadow DOM.
:near(селектор)Есть подходящий sibling в любом направлении и на любом расстоянии.
:sibling-distance(previous, 2, селектор)Второй предыдущий sibling соответствует селектору.
:sibling-distance(next, 3, селектор)Третий следующий sibling соответствует селектору.
:children(селектор, >=2)Количество подходящих непосредственных детей удовлетворяет условию.
:sibling-position(2)Элемент является вторым ребёнком родителя.
:matches-position(2)Оставить второй результат полного правила. Несколько номеров разделяются запятыми или пробелами.

Условия живой страницы и доступности

СинтаксисЗначение
:visible(...)Проверяет видимость на живой странице.
:size(...)Проверяет отображаемый размер.
:style(...)Проверяет вычисленный стиль.
:property(...)Проверяет JavaScript-свойство DOM.
:accessible(...)Проверяет признаки доступности.

Эти условия зависят от состояния браузера и могут быть недоступны при поиске по сохранённому DOM-снимку.

Iframe и Shadow DOM

СинтаксисЗначение
:in-frame(...)Ограничивает поиск содержимым iframe.
:in-shadow(...)Ограничивает поиск Shadow DOM.
:frame-has(селектор)Документ iframe содержит совпадение.
:has-frame(...)Элемент содержит iframe, удовлетворяющий условию.

Для cross-origin iframe и закрытых Shadow Root действуют ограничения браузера и разрешений расширения.

Примеры

div[class]:text-contains("Скрыть рекламу"):near(div.new-menu)
div.target:sibling-distance(previous, 2, div.new-menu)
div:style-property("--rc-adaptive-width")
section:has(> div:attr-count(=2) > span:own-text("Реклама"))
div:attr-count(=1):class-count(=2):matches-position(2)

Совместимость

Версия 1 является контрактом совместимости. Можно добавлять новые псевдоклассы и необязательные возможности, не меняя смысл существующих конструкций. Несовместимое изменение потребует новой внутренней версии синтаксиса. Старые правила без поля syntaxVersion продолжат считаться правилами версии 1.
