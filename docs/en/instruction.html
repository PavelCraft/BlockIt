What is BlockIt?

Advertising websites and popular blockers are locked in a constant arms race: website developers look for ways around public filter lists, while blocker developers continually update those lists.

BlockIt takes a different approach to blocking ads and other unwanted elements. Instead of relying only on shared filter lists, you create rules for specific elements on the sites you use. Unless you share those rules, a website does not know which element traits your BlockIt rules rely on, making it harder to deliberately break them.

Key features

  • Easy to use: you do not need to memorize CSS selector, XPath, or BlockIt rule syntax. Sometimes copying a selector from DevTools and pasting it into the extension is enough.
  • Flexibility:
    • You decide whether to remove an element or hide it
    • You decide which elements to block and which to keep
    • You decide which rules to keep, disable, or delete
    • Both CSS selectors and XPath expressions are supported
    • Rules also apply inside iframes and Shadow DOM
  • Privacy: all rules are stored locally in your browser and are not sent anywhere.
  • BlockIt syntax: complex cases can use syntax that extends standard CSS selectors. See the BlockIt syntax documentation when needed.
  • Rules grouped by site: rules are automatically grouped for the current site and for all other sites, making them easier to manage.
  • Share settings: export your rules to a file to share them with other users.
  • Multiple languages: the extension follows your browser language. Russian, English, French, German, Spanish, Portuguese, Chinese, and Japanese are supported. If your language is unavailable, the interface is shown in English.
  • Open source: the extension is developed under the BSD-3-Clause license. You can contribute, suggest improvements, and inspect the code on GitHub.

Tips for choosing an element to block

Before copying a selector or HTML, identify exactly which element should be blocked.

  • Use DevTools highlighting. Hover over rows of HTML to highlight the corresponding page elements and see exactly which area will be blocked.
  • Choose the outermost element without including anything extra. Find the outermost container that contains only the block you need. An element that is too deep may leave part of an ad visible; one that is too broad may hide useful content.
  • Watch the element count. BlockIt shows the number of matches after you paste a rule. One match is usually safer. Multiple matches are fine if you checked every one; 0 means the rule will find nothing.

If a rule blocks too much or nothing at all, delete it and select a different element higher or lower in the HTML tree.

Blocking modes

  • Remove: removes the element from the HTML and frees its space. This works in most cases but can occasionally change the layout.
  • Hide: makes the element invisible while preserving its space. Use this if removing it makes the page look worse.

Ways to create a rule Back to top

First find the element in DevTools and inspect its tag, classes, and attributes.

What might help?

Enable the relevant hints. Highlighting does not hide other methods; it only suggests a sensible place to start.

Recommended methods are highlighted below. Select any method to open its detailed instructions.

1Copy a CSS selector from DevTools Select to read

Start here to quickly test whether a standard selector can block the element. DevTools creates it automatically: select the element, then choose “Copy” → “Copy selector”.

Paste the selector into BlockIt’s main field, check the match count, and add the rule. If it becomes unreliable after a refresh, use StableHTMLFinder or the rule builder.

1
2Copy XPath from DevTools Select to read

XPath describes a path to an element through the page structure. It can help when classes and other attributes are unstable but the path itself remains unchanged. Choose “Copy XPath” in DevTools, then paste the expression into BlockIt’s main field.

Inspect the copied expression. Chrome may build an XPath around an id. If that ID changes, the XPath is unstable too. An absolute path with position numbers will break when the HTML structure changes.

BlockIt evaluates XPath separately in the main document and in each iframe, so an XPath copied from inside an iframe may work. Browsers do not evaluate XPath across a Shadow DOM boundary. In that case, use the rule builder or StableHTMLFinder to create a CSS-based or extended BlockIt rule.

1
3Create a quick rule from HTML Select to read

This method gives you more control than a ready-made DevTools selector: after parsing the HTML, you choose which attributes go into the selector.

1
Do not keep every attribute automatically. A class or ID made of random-looking characters may change on the next page load.
4Use StableHTMLFinder Select to read

StableHTMLFinder helps when classes and IDs are obfuscated, change between loads, or the page contains many similar blocks. It is often easier than inspecting HTML manually, but analysis takes time because the extension must load the page several times.

1

StableHTMLFinder does not block elements itself. It helps you choose a foundation for a BlockIt rule:

  • CSS selector — the simplest option when it uses stable traits and finds the correct number of elements.
  • BlockIt rule — use this when precise matching needs extended syntax unavailable in standard CSS.
  • Inspect the map yourself — study stable traits of the element and its surroundings, then enter them in the BlockIt rule builder. Use this when the generated results are not precise enough.
5Open the rule builder Select to read

The rule builder is a powerful tool for creating precise rules without knowing CSS, XPath, or BlockIt syntax. It works for both stable and unstable elements: a rule can use text, attribute or class counts, sibling position, and surrounding elements instead of a specific class.

Copy the element’s HTML in DevTools, open BlockIt’s “Advanced mode,” paste the HTML into the corresponding field, and click “Open rule builder.”

Element card

Each card describes one HTML element: its tag, attribute count, and conditions based on attributes, text, and position.

Relationship tree

Ancestors appear above. Descendants appear below with an indent. Siblings are shown at the same nesting level.

Stable traits

You can disable automatically inserted values. Do not use changing IDs and classes merely because they were found in the HTML.

Testing

Check the match count immediately, then use “Check after refresh” to verify that the result remains stable.

Conditions available in a card

  • Tag: specify it, or leave it blank when it is not important.
  • Attribute count: exactly, at least, or at most the specified number.
  • Attributes: conditions for names and values; for class, you can also set the number of classes.
  • Text: the element’s own text or all text inside it; exact match, prefix, suffix, substring, or regular expression.
  • Sibling position: the element’s position among children of the same parent.

Related elements

You can add a direct parent or any ancestor to the target and its ancestors. The target can also have a child, descendant, or sibling; siblings can have descendants of their own. Related elements have an “May be absent” switch.

Sibling position is an element’s place among children of one parent. Position in rule results is its place among all elements found by the complete rule. These are different conditions.

Preview and testing

Read the plain-language description in “Rule preview.” It helps reveal an attribute, text condition, or relationship that was included by accident. Then check the match count on the current page and after a refresh.

Example: configuring one rule for several elements

  1. Enable “Sibling position” and enter the positions of the required elements: 2, 3, and 5 in this example.
  2. Keep exact matching for the class attribute name.
  3. Remove the unreliable part of the class value and change “value: exactly” to “value: contains”.
  4. Disable “Class count” if that number is not significant and may change.
  5. Read the description under “Rule preview” and check that every condition is necessary.
  6. Close DevTools on the target page and click “Check after refresh.” Some sites load different content while DevTools is open.
  7. Make sure the number of matches does not change after the refresh. This indicates that the rule is stable.
  8. Click “Create rule.”
1

When to switch methods

Start with a CSS selector from DevTools for a quick result. A quick HTML rule is useful when the element traits look stable but you want control over which attributes are used. If the traits are unstable or random-looking, or the page has many similar blocks, use StableHTMLFinder or the rule builder.

CSS selector reference Back to top

What are selectors?

Selectors find an element on a web page by its properties: tag, class, identifier, attributes, or position in the HTML structure.

In CSS styles, selectors apply formatting. In BlockIt, selectors are used only for finding elements. We do not set colors, fonts, or spacing—we simply find an element in order to block it.

These examples will help you read and make small edits to ordinary CSS selectors.

How to check a selector

  1. Open the Elements tab in DevTools.
  2. Press Ctrl + F, or Cmd + F on a Mac.
  3. Paste the selector into the search field.
  4. DevTools highlights all matches and shows their count, for example 1 of 3.
1

Selector types

Universal selector (*)

Finds every element on the page. Use it with care: it returns everything in the HTML.

Selector: *

What it finds: every element without exception.

Tag selector

Finds all elements with the specified HTML tag.

Selectors: h1, p, button, div

What they find:

  • h1 — all first-level headings;
  • p — all paragraphs;
  • button — all buttons;
  • div — all <div> containers.

Class selector (.class)

Finds all elements with the specified class in their class attribute. Write multiple classes together without spaces.

Selectors: .card, .card__title, .card.featured

What they find:

  • .card — all elements with the card class;
  • .card__title — all elements with the card__title class;
  • .card.featured — elements that have both the card and featured classes.

An element may have other classes as well: for example, class="card featured compact" also matches .card.featured. To match the complete class string exactly, you can use [class="card featured"], but that selector depends on class order and does not allow additional classes.

ID selector (#id)

Finds an element with a unique id. A page should contain only one element with that ID.

Selectors: #salad-cat, #confused-cat, #bread-cat

What they find:

  • #salad-cat — the element with id="salad-cat";
  • #confused-cat — the element with id="confused-cat";
  • #bread-cat — the element with id="bread-cat".

Attribute selector ([attribute="value"])

You can check an attribute for an exact value or merely for its presence. Write multiple conditions together.

Selectors: [data-type], [data-type="description"], [data-type="description"][aria-label="Card"], [class~="card"], [class="card featured"]

What they find:

  • [data-type] — elements with a data-type attribute of any value;
  • [data-type="description"] — elements whose data-type value is exactly description;
  • [data-type="description"][aria-label="Card"] — elements where both attributes match;
  • [class~="card"] — elements whose class list contains the separate class card;
  • [class="card featured"] — elements whose entire class attribute exactly matches the given string.
Ways to compare a value
[href^="https://"]
the value starts with https://
[src$=".png"]
the value ends with .png
[class*="advert"]
the value contains advert anywhere
[class~="card"]
a space-separated word list contains the separate word card
[lang|="en"]
the value equals en or starts with en-, such as en-US
[aria-label*="advertisement" i]
the value contains “advertisement,” ignoring case

A selector checks only the attributes it lists and does not prohibit others. For example, [data-type="description"][aria-label="Card"] finds <div data-type="description" aria-label="Card" title="Details">: the extra title attribute does not prevent a match. A standard CSS selector cannot require an element to have no other attributes.

Combined selectors

A tag, class, ID, and attribute conditions can be combined without spaces so that every trait applies to the same element.

Selectors: h2.card__title, div.card.featured, div[data-type="description"], article.card[data-type="advertisement"][aria-label="Advertisement"]

What they find:

  • h2.card__title — an <h2> with the card__title class;
  • div.card.featured — a <div> with the card and featured classes; other classes are allowed;
  • div[data-type="description"] — a <div> with the specified attribute; other attributes are allowed;
  • article.card[data-type="advertisement"][aria-label="Advertisement"] — an <article> with the card class whose attribute values exactly equal data-type="advertisement" and aria-label="Advertisement".

Descendant selector (space)

Finds elements located inside another element at any nesting level.

Selector: .card .btn

What it finds: all elements with the btn class inside an element with the card class.

Child selector (>)

Finds elements that are direct children of another element. It searches only one level down.

Selector: .card__body > .card__title

What it finds: elements with the card__title class that are direct children of an element with the card__body class.

Adjacent sibling selector (+)

Finds the element that is the next sibling of another element at the same nesting level.

Selector: #confused-cat + .card__description

What it finds: a <p> immediately following the element with id="confused-cat".

Position pseudo-class

Selects elements by their position among siblings.

Selector: .card__actions :nth-child(2)

What it finds: the second child inside an element with the card__actions class.

Standard CSS selectors have limitations. They cannot describe an attribute or class count without listing them, an element’s own text, arbitrary text inside it, regular expressions, or attribute-name patterns. For example, [data-*] is not a standard CSS selector. BlockIt rules are used for these cases: they extend standard CSS syntax with constructs such as [data-*], :attr-name(/^data-/), and other conditions. Read the BlockIt syntax documentation.

What are iframe and Shadow DOM? Back to top

iframe is a separate web page embedded inside another page. Its content lives in its own document, so a regular search from the parent page cannot simply cross into it.

What an iframe looks like in HTML 
<main>
  <h1>Main page</h1>
  <iframe src="advertisement.html"></iframe>
</main>

The markup from advertisement.html loads as a separate document inside the <iframe>.

Shadow DOM is an isolated internal component tree. A site uses it to separate a component’s markup from the rest of the page; a closed shadow root also hides this tree from ordinary page scripts.

What Shadow DOM looks like in DevTools 
<video-player>
  #shadow-root (open)
    <button class="play">Play</button>
</video-player>

The button is inside the <video-player> component’s shadow root, not in the main page’s ordinary tree.

These create search boundaries for blockers: a rule must run not only in the main document but also inside every accessible iframe and shadow root. Not every blocker does this. BlockIt applies CSS selectors and extended rules inside iframe and Shadow DOM, but XPath works only in documents and cannot cross a Shadow DOM boundary.

Managing rules Back to top

Created rules appear in the list for the current site or in the list of rules not tied to a domain. Rules made in the builder can be edited or deleted; disabled rules remain in the list with a corresponding label.

Disabling and deleting

How do I disable a rule?

Find the rule in “Active rules” and click “Disable.” The rule stays in place with a “Disabled” label but is no longer applied. If it has already removed an element from the open page, refresh the page to restore its original content.

How do I delete a rule?

Find the rule in “Active rules” and click “Delete.” To restore an element already removed from the open page, reload it with F5 or the tab’s refresh button.

Export and import

Export saves rules to a file. Import adds rules from such a file or replaces the current list with them. Use this feature to transfer settings and share them between devices.

1

Checking rules

Open the page where you want to check the rules, then open BlockIt. In the “For this site: <domain>” group heading, click “Check rules.”

The check shows whether saved rules find elements on the open page. You can take one measurement or enable “Check stability” and choose several reloads. During measurement, BlockIt temporarily stops applying rules, reloads the page, and shows each rule’s match count on every load.

  • Works: the rule finds the same non-zero number of elements in every check.
  • Unstable: the rule finds elements, but their number changes between loads.
  • Did not work: no matches were found on the tested page.
  • Error: the rule could not be executed.

The check includes rules for the current base domain and rules not tied to a domain. BlockIt does not separate subdomains when saving a normal domain binding: for example, a rule created on e.mail.ru is stored for mail.ru. However, elements are checked on the exact page from which you opened diagnostics. A working rule for one subdomain or site section may therefore receive “Did not work” on another subdomain or URL. For a reliable result, open the page for which the rule was created and start the check there.

The check measures matches, not what the elements are for. A non-zero result means the rule found something, but does not guarantee that it found only the elements you intended to block. Compare the match count with the result on the page itself.

Troubleshooting Back to top

Something else was blocked along with the advertisement

This happens when the selector is too broad and finds not only the advertisement but other page elements as well.

What to do:

  • Delete the rule as described under “Managing rules”.
  • Select a more precise element: move up or down the HTML tree to find a container that contains only the advertisement.
  • Check the match count before adding a rule. Multiple matches are acceptable only when every matched element should be blocked.
The rule did not work
  • Possible cause 1: The selected element is not the outermost one. Move higher in the HTML tree and copy the selector for the parent container.
  • Possible cause 2: The site uses dynamic classes (obfuscation). A copied selector may stop working after a refresh. Under “Ways to create a rule”, mark the traits as unstable and use a suggested method such as StableHTMLFinder or the builder.
  • Possible cause 3: The page changed its structure after the rule was created. Check the element’s current HTML and the match count. If the site rebuilt the block, copy the selector again or refine the rule in the builder.
  • Possible cause 4: The rule was created for another domain. Check whether it is in “For this site” or “For other sites.”
The selector does not find any elements
  • Check your selector: Open DevTools (F12), go to the Elements tab, press Ctrl + F (or Cmd + F on a Mac), and enter the selector in the search field. If the search finds no elements, the selector is incorrect.
The layout broke after removing an element and looks worse than before
  • Solution: Delete the rule and create it again using “Hide”. This preserves the element’s space and avoids disrupting the layout.
The selector finds too many elements

First check the count and identify which elements are in the results. If the required element has a stable class or attribute, add it to the selector. If a simple selector is not enough, open the rule builder: it can account for text, class and attribute counts, sibling position, or relationships with surrounding elements. After refining the rule, check it again on the current page and after a refresh.

I cannot make sense of the page’s HTML structure

Use StableHTMLFinder: it compares several loads and builds a stability map. Find the required element with map search, then inspect its stable traits and surrounding elements.

If the markup looks especially heavily obfuscated, the site may serve a different page variant to VPN connections. If appropriate, temporarily disable the VPN, reload the page, and repeat the analysis. This does not help on every site, but it lets you check whether the more complex markup is tied to the page variant your connection receives.

Nothing helps

Try combining the stable traits found by StableHTMLFinder with the BlockIt builder. This lets you construct a rule manually using both the element and its surroundings.

If you have tried several methods but the rule still does not work or the extension produces errors, send a report through BlockIt’s Feedback form. Include the page URL, the rule, and screenshots if possible.
