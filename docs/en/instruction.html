What is BlockIt? Back to top

Websites that show ads and popular ad blockers are in a constant "arms race": developers keep finding new ways to show you ads, and blockers keep finding ways to hide them.

BlockIt offers a different approach. Instead of relying on common filter lists, you create your own rules to block specific elements. Your rules remain known only to you unless you choose to share them, making them much more resistant to being bypassed.

Key Features:

  • Ease of use: Just copy a selector from Developer Tools and paste it into the extension.
  • Flexibility:
    • Supports both CSS selectors and XPath expressions
    • You decide whether to remove an element or hide it
    • You decide which elements to block and which to keep
    • You decide which blocking rules to keep and which to delete
  • Privacy: All rules are stored locally in your browser and never sent anywhere.
  • Site-based grouping: Rules are automatically grouped for the current site and for all others. This makes them easier to manage.
  • Share settings: You can share your rules with other users by exporting them to a file.
  • Multi-language support: The extension interface automatically switches to the language set in your browser. Supported languages: Russian, English, French, German, Spanish, Portuguese, Chinese, and Japanese. If your language is not supported, the interface will default to English.
  • Open source: The extension is developed under the BSD-3-Clause license. You can contribute to the project, suggest improvements, and explore the code on GitHub.

Quick Start Back to top

Installation

Method 1 (recommended): Go to the Chrome Web Store, find the BlockIt extension, and click "Install". After installation, be sure to pin the extension to the browser toolbar by clicking the puzzle icon next to the address bar and selecting "Pin" next to BlockIt.

How to block an element

  1. Right-click on the element you want to block and select "Inspect" (or "Inspect Element"). This always takes you directly to the element in the HTML tree.
  2. In the HTML tree, find the element you need. To make sure you've selected the right element, hover your cursor over the code lines — the corresponding elements on the page will be highlighted. Choose the outermost element that fully covers the block you want to block.
  3. Right-click the element in the tree → Copy → Copy selector. For XPath: Copy XPath.
  4. Open the BlockIt extension, paste the copied selector into the input field, choose the blocking mode, and click "Add Rule".
  5. Done! The rule appears in the active rules list, and the element disappears from the page.
  6. To close Developer Tools, press F12 or click the close (X) button in the top-right corner of the DevTools panel.

What do the blocking modes mean?

  • Remove (works for most cases): The element is completely removed from the page HTML, and its space is freed up for other elements. However, this option can sometimes cause the layout to break.
  • Hide: The element becomes invisible but continues to occupy the same space on the page. The layout does not break.

Advanced Features Back to top

Blocking with XPath

XPath is useful on websites that use dynamic classes (obfuscation) when CSS selectors are unstable.

How to copy XPath:

  1. Find the element via "Inspect".
  2. Right-click the element in the code → Copy → Copy XPath.
  3. Paste the expression into the BlockIt input field. The extension will automatically recognize it as XPath, and you do not need to enable Advanced mode for this.

Advanced mode

In basic mode, the extension offers a simple field for entering a selector. For more fine-tuned rule creation and additional tools, there is Advanced mode. To enable it, click the corresponding button in the extension interface.

In this mode, you get access to:

  • HTML parser: Paste the HTML code of an element, and the extension will automatically suggest a selector composed of its attributes.
  • Attribute editing: After parsing, you'll see a list of the element's attributes and can remove unreliable ones (e.g., dynamically generated classes) to refine the selector.
  • Manual attribute addition: You can manually add an attribute and its value if you need to further refine the selector.
  • Export and import rules: Share your rules with others or transfer them between devices.

HTML parser, editing, and adding attributes

These three tools work together as a unified workflow for creating precise selectors without needing to remember syntax:

  1. Copy the HTML code of the element (Right-click → Copy → Copy element).
  2. Enable Advanced mode in the extension and paste the HTML code into the corresponding field. Click "Parse". The extension will parse the code and show you the tag and a list of all its attributes.
  3. Edit the suggested attribute list. Keep only the attributes that are least likely to change in the future. For example, id and class values that look like dynamically generated gibberish are poor choices for this purpose. The selector in the input field will update automatically with every change you make.
  4. Add attributes manually if needed. If the suggested set of attributes isn't enough to create a unique selector, you can add your own.
  5. Click "Add Rule" and confirm that it has been added and the element has been removed from the page.

Tips for Choosing an Element to Block Back to top

The methods below are ranked from simplest to most advanced. Start with the first and move to the next if the previous one doesn't work.

1. Copy the selector from DevTools

This is the simplest method that works for most websites. Instructions are described in the "How to block an element" section.

2. Copy XPath from DevTools

Use this if the copied selector doesn't work due to dynamic classes on the site. Instructions for copying XPath are in the "Blocking with XPath" section.

3. Use the HTML parser (in Advanced mode)

This method is convenient if you understand selector theory but don't remember the exact syntax. You paste the HTML code of an element, and the extension suggests a selector based on its attributes.

4. Edit the attribute list (in Advanced mode)

After using the HTML parser, you'll see a list of all attributes of the element. Keep only those attributes that are least likely to change in the future. Dynamically generated classes (gibberish) are poor choices for this purpose.

5. Add attributes manually (in Advanced mode)

If none of the automatic methods provide a stable selector, you can manually add a unique attribute and its value to narrow the search.

6. Write a selector manually

Requires a basic understanding of CSS selector syntax. This gives you more control and stability. To learn the basics, check out the Selector Cheatsheet or the CSS and XPath Selector Reference.

Export and Import Rules Back to top

This feature allows you to share rules with others or transfer them between computers. Available in Advanced mode.

  • Export: Saves all your rules to a JSON file.
  • Import: Loads rules from a JSON file. You can replace all current rules or add new ones (duplicates will be skipped).

How to import rules?

  • In Advanced mode, click the "Import" button, a window will open, click "Choose File" and select the file.
  • Choose whether to add the imported rules to your list or replace your list with the imported ones. Depending on what you want, click "Replace All" or "Add".
  • If successful, you'll see an import confirmation and the new rules will appear in your active rules list in the extension window.

Troubleshooting (FAQ) Back to top

My rule didn't work

  • Possible reason #1. The chosen element is not the outermost one: Try moving up the HTML tree and copying a selector for the parent container.
  • Possible reason #2. The site uses dynamic classes (obfuscation): In this case, the copied selector may stop working. Use XPath or write a selector manually.
  • Possible reason #3. The element is loaded dynamically: The extension automatically reapplies rules when the page changes. If that didn't help, try refreshing the page.
  • Possible reason #4. The rule was created for a different domain: Check that the rule is in the "For this site" or "For other sites" group.

The selector doesn't find any elements

  • Check your selector: Open DevTools (F12), switch to the "Elements" tab, press Ctrl+F (or Cmd+F on Mac), and enter your selector in the search box. If the search finds nothing, your selector is incorrect.
  • The page uses Shadow DOM: In this case, standard selectors may not work. Try using XPath or searching for the element inside the shadow root.
  • The element loads after the script runs: Some elements appear with a delay. Try refreshing the page or waiting.

After removing an element, the layout broke and looks worse than with the ad

  • Solution: Delete the rule and recreate it, but select the "Hide" mode. This preserves the space on the page and keeps the layout intact.

The selector finds too many elements

Refine the selector by adding more attributes or using a more specific path. In Advanced mode, you can manually add a unique attribute to narrow the search.

Nothing helps

If you've tried everything and the element stubbornly refuses to be blocked, maybe the best thing you can do is piss on that site, leave it, and forget it exists. 😄

Selector Cheatsheet Back to top

What are selectors?

Selectors are a way to find a specific element on a web page by its properties: tag, class, ID, attributes, or position in the HTML structure.

Unlike CSS styles, where selectors are used to apply styling, in BlockIt selectors are used only for finding elements. We don't set colors, fonts, or margins — we just find the element to block it.

How to open Developer Tools

Developer Tools (DevTools) are the primary tool for working with selectors. Here's how to open them:

Action Result
Press F12 DevTools panel opens
Or press Ctrl + Shift + I Same thing
Or right-click an element → "Inspect" DevTools opens with the element highlighted

How to customize Developer Tools

Interface language

  1. Open DevTools (F12).
  2. Click the gear icon (⚙️) in the top-right corner → Settings.
  3. In the "Language" section, select your preferred language from the dropdown.
  4. Close and reopen DevTools.

Panel docking

  1. Click the three dots (⋮) in the top-right corner of DevTools.
  2. Choose one of the options:
    • Dock to right (default)
    • Dock to bottom — convenient if you have a wide monitor
    • Dock to left — if you prefer a different layout
    • Undock into separate window — move it to another monitor

How to test selectors in Developer Tools

The fastest way to check if your selector works is to use search (Ctrl + F):

  1. Open DevTools (F12) and go to the "Elements" tab.
  2. Press Ctrl + F (or Cmd + F on Mac).
  3. Type your selector into the search box.
  4. DevTools will highlight all elements matching the selector.

The search bar shows how many elements were found (e.g., 1 of 3). This helps you understand how precise your selector is.

Now let's put this knowledge into practice. Open the example.html page and open DevTools. Try entering the selectors from the table below and see which elements they find.

Selector types

1. Universal selector (*)

Finds all elements on the page. Use with caution — it will return everything in the HTML.

Selector: *

What it finds: All elements without exception.

2. Type selector

Finds all elements with the specified HTML tag.

Selectors: h1, p, button, div

What it finds:

  • h1 — all first-level headings
  • p — all paragraphs
  • button — all buttons
  • div — all <div> containers

3. Class selector (.class)

Finds all elements with the specified class in the class attribute.

Selectors: .card, .card__title, .btn--view

What it finds:

  • .card — all elements with class card
  • .card__title — all elements with class card__title
  • .btn--view — all elements with class btn--view

4. ID selector (#id)

Finds an element with a unique id. There should only be one such element on the page.

Selectors: #salad-cat, #confused-cat, #bread-cat

What it finds:

  • #salad-cat — element with id="salad-cat"
  • #confused-cat — element with id="confused-cat"
  • #bread-cat — element with id="bread-cat"

5. Combined selectors

You can combine tag, class, and ID for more precise searching.

Selectors: h2.card__title, div.card, p.card__description, button.btn--edit

What it finds:

  • h2.card__title — <h2> with class card__title
  • div.card — <div> with class card
  • p.card__description — <p> with class card__description
  • button.btn--edit — <button> with class btn--edit

6. Attribute selector ([attribute="value"])

Finds elements with a specific attribute and value.

Selectors: [data-type="description"], [data-type="title"]

What it finds:

  • [data-type="description"] — all elements with data-type="description"
  • [data-type="title"] — elements with data-type="title"

7. Descendant selector (space)

Finds elements that are inside another element (at any nesting level).

Selector: .card .btn

What it finds: All elements with class btn that are inside an element with class card.

8. Child selector (>)

Finds elements that are immediate children of another element. Search is only one level deep.

Selector: .card__body > .card__title

What it finds: Elements with class card__title that are direct children of an element with class card__body.

9. Adjacent sibling selector (+)

Finds an element that is the next sibling of another element at the same nesting level.

Selector: #confused-cat + .card__description

What it finds: A paragraph (<p>) that immediately follows the element with id="confused-cat".

10. Positional pseudo-classes

Select elements based on their position among their siblings.

Selector: .card__actions :nth-child(2)

What it finds: The second child element inside the element with class card__actions.

🔍 How to check your answers

Once you've written a selector, paste it into the DevTools search bar (Ctrl + F). The search bar will show how many elements were found (e.g., 1 of 3).

  • If you were looking for a specific single element (e.g., by id), the result should be 1 of 1.
  • If you were looking for a group of elements (e.g., all paragraphs with a certain class), the result may be 1 of 3 or more — that's normal.
  • The important thing is that the highlighted elements are exactly what you were looking for. Check visually: are the right elements highlighted on the page?

If the wrong elements are highlighted, refine the selector by adding more conditions.
