BlockIt とは

広告を表示するサイトと一般的なブロッカーは、公開フィルターを回避する側と更新する側の終わりのない競争を続けています。

BlockIt は別の方法を採ります。共有リストだけに頼らず、利用するサイトの特定要素に対して自分でルールを作ります。ルールを共有しない限り、サイト側はどの特徴を利用しているか分からず、意図的に無効化しにくくなります。

主な特徴

  • 簡単：CSS セレクター、XPath、BlockIt ルールの構文を覚える必要はありません。DevTools からセレクターをコピーして貼り付けるだけで済む場合もあります。
  • 柔軟性：
    • 要素を削除するか非表示にするか選べます
    • ブロックする要素と残す要素を選べます
    • ルールを維持、無効化、削除できます
    • CSS セレクターと XPath 式に対応します
    • iframe と Shadow DOM 内にもルールを適用します
  • プライバシー：ルールはブラウザー内に保存され、外部へ送信されません。
  • BlockIt 構文：複雑な場合は標準 CSS を拡張した構文を利用できます。必要に応じてBlockIt 構文のドキュメントを参照してください。
  • サイト別グループ：現在のサイト用とその他のサイト用に自動で整理されます。
  • 設定の共有：ルールをファイルへ書き出して共有できます。
  • 多言語：ブラウザーの言語に従います。ロシア語、英語、フランス語、ドイツ語、スペイン語、ポルトガル語、中国語、日本語に対応し、未対応の場合は英語を表示します。
  • オープンソース：BSD-3-Clause ライセンスで開発されています。GitHub でコードを確認し、改善を提案できます。

ブロックする要素を選ぶヒント

セレクターや HTML をコピーする前に、対象を正確に特定します。

  • DevTools の強調表示を使います。HTML の行にカーソルを合わせ、対応する範囲を確認します。
  • 余分な内容を含まない最も外側の要素を選びます。深すぎると広告の一部が残り、広すぎると必要な内容まで隠れます。
  • 要素数を確認します。通常は 1 件が安全です。すべて確認済みなら複数件でも構いません。0 は何も見つからないことを示します。

ブロックしすぎる、または何もブロックしない場合は削除し、HTML ツリーの別の要素を選びます。

ブロック方式

  • 削除：要素を HTML から削除して空間を詰めます。レイアウトが変わる場合があります。
  • 非表示：空間を残したまま見えなくします。削除でレイアウトが崩れる場合に使います。

ルールの作成方法 先頭へ

まず DevTools で要素を探し、タグ、クラス、属性を確認します。

どの方法が適していますか？

該当する項目を有効にしてください。他の方法は隠れず、推奨される開始点だけが強調されます。

推奨方法が下で強調されます。選択すると詳しい手順が開きます。

1DevTools から CSS セレクターをコピー 選択して読む

BlockIt に貼り付け、一致数を確認して追加します。再読み込み後に不安定なら StableHTMLFinder またはルールビルダーを使います。

2DevTools から XPath をコピー 選択して読む

式を確認してください。Chrome が id を基準にする場合、その ID が変わると XPath も不安定です。位置番号を含む絶対パスは構造変更で壊れます。

BlockIt はメイン文書と各 iframe で XPath を別々に評価します。iframe 内でコピーした XPath は機能する場合があります。一方、XPath は Shadow DOM の境界を越えません。その場合はルールビルダーまたは StableHTMLFinder を使います。

1
3HTML から簡易ルールを作成 選択して読む

HTML を解析した後、セレクターに含める属性を自分で選べます。

1
すべての属性をそのまま残さないでください。ランダムなクラスや ID は次回変わる可能性があります。
4StableHTMLFinder を使う 選択して読む

StableHTMLFinder は、クラスや ID が難読化される、読み込みごとに変わる、類似ブロックが多い場合に役立ちます。手作業より簡単なことが多い一方、複数回読み込むため時間がかかります。

1

StableHTMLFinder 自体はブロックしません。BlockIt ルールの基礎を選ぶためのツールです。

  • CSS セレクター：安定した特徴で正しい数を見つける場合の最も簡単な選択です。
  • BlockIt ルール：標準 CSS では表せない精密な条件が必要な場合に使います。
  • マップを自分で確認：要素と周囲の安定した特徴を調べ、ルールビルダーへ入力します。
5ルールビルダーを開く 選択して読む

CSS、XPath、BlockIt 構文を知らなくても精密なルールを作れる強力なツールです。テキスト、属性・クラス数、兄弟位置、周囲の要素を条件にできます。

DevTools で HTML をコピーし、BlockIt の「詳細モード」を開いて貼り付け、「ルールビルダーを開く」を押します。

要素カード

各カードはタグ、属性数、属性・テキスト・位置の条件を表します。

関係ツリー

祖先は上、子孫は字下げして下、兄弟は同じ階層に表示されます。

安定した特徴

自動入力値は無効化できます。変化する ID やクラスを、HTML にあったという理由だけで使わないでください。

確認

一致数を確認し、「再読み込み後に確認」で結果が安定しているか確かめます。

カードで指定できる条件

  • タグ：重要なら指定し、不要なら空欄にします。
  • 属性数：指定数と同じ、以上、以下を選べます。
  • 属性：名前と値の条件を指定します。class ではクラス数も指定できます。
  • テキスト：要素自身または内部全体のテキストに対し、完全一致、前方・後方一致、部分一致、正規表現を使えます。
  • 兄弟内の位置：同じ親の子要素の中での位置です。

関連要素

対象やその祖先に直接の親または任意の祖先を追加できます。対象には子、子孫、兄弟も設定でき、兄弟に子孫を追加することもできます。関連要素には「存在しなくてもよい」スイッチがあります。

兄弟内の位置は同じ親の子要素の中での順位、ルール結果内の位置は完成したルールが見つけた全要素の中での順位です。異なる条件です。

プレビューと確認

「ルールのプレビュー」にある文章を読み、誤って含めた属性、テキスト条件、関係がないか確認します。その後、現在のページと更新後の一致数を調べます。

例：複数の要素に１つのルールを作る

  1. 「兄弟内の位置」を有効にし、対象の位置を入力します。この例では2、3、5 です。
  2. class 属性名の完全一致はそのままにします。
  3. クラス値の不安定な部分を除き、「値：完全一致」を「値：含む」に変えます。
  4. クラス数が重要でなく変化しうるなら、その条件を無効にします。
  5. 「ルールのプレビュー」を読み、条件がすべて必要か確かめます。
  6. 対象ページの開発者ツールを閉じてから「更新後に確認」を押します。開いていると別の内容が読み込まれるサイトがあります。
  7. 更新後も一致数が変わらないことを確認します。ルールの安定性を示す目安です。
  8. 「ルールを作成」を押します。
1

別の方法に切り替える目安

素早く試すなら開発者ツールの CSS セレクターから始めます。特徴が安定しているものの使う属性を選びたい場合は、HTML からの簡易ルールが便利です。特徴が不安定、無作為に見える、または似たブロックが多い場合は StableHTMLFinder やルールビルダーを使います。

CSS セレクター早見表 先頭へ

セレクターとは

セレクターは、タグ、クラス、ID、属性、HTML 構造内の位置から要素を見つけます。

CSS では書式指定に使いますが、BlockIt では要素を見つけるためだけに使います。

以下の例で一般的な CSS セレクターを読んだり少し編集したりできます。

セレクターを確認する

  1. DevTools の 「要素」 / “Elements” を開きます。
  2. Ctrl + F（Mac は Cmd + F）を押します。
  3. 検索欄に貼り付けます。
  4. 一致箇所と件数（例：1 of 3）が表示されます。
1

セレクターの種類

全称セレクター (*)

ページ内のすべてを見つけるため、注意して使います。

セレクター： *

見つかるもの：例外なくすべての要素。

タグセレクター

指定した HTML タグの要素をすべて見つけます。

セレクター： h1, p, button, div

見つかるもの：

  • h1 — すべての第１階層見出し。
  • p — すべての段落。
  • button — すべてのボタン。
  • div — すべての <div> コンテナー。

クラスセレクター (.class)

指定クラスを持つ要素を見つけます。複数クラスは空白なしで続けます。

セレクター： .card, .card__title, .card.featured

見つかるもの：

  • .card — card クラスを持つすべての要素。
  • .card__title — card__title クラスを持つすべての要素。
  • .card.featured — card と featured の両方を持つ要素。

ほかのクラスがあっても一致します。たとえば class="card featured compact" も .card.featured に一致します。クラス文字列全体を厳密に指定するなら [class="card featured"] を使えますが、順序に依存し、追加クラスを許しません。

ID セレクター (#id)

固有の id を持つ要素を見つけます。

セレクター： #salad-cat, #confused-cat, #bread-cat

見つかるもの：

  • #salad-cat — id="salad-cat" の要素。
  • #confused-cat — id="confused-cat" の要素。
  • #bread-cat — id="bread-cat" の要素。

属性セレクター ([attribute="value"])

属性の正確な値または存在を確認できます。複数条件は続けて書きます。

セレクター： [data-type], [data-type="description"], [data-type="description"][aria-label="Card"], [class~="card"], [class="card featured"]

見つかるもの：

  • [data-type] — 値に関係なく data-type 属性を持つ要素。
  • [data-type="description"] — data-type の値が正確に description の要素。
  • [data-type="description"][aria-label="Card"] — 両方の属性が一致する要素。
  • [class~="card"] — クラス一覧に独立した card がある要素。
  • [class="card featured"] — class 属性全体が指定文字列と正確に一致する要素。
値の比較方法
[href^="https://"]
値が https:// で始まる
[src$=".png"]
値が .png で終わる
[class*="advert"]
値のどこかに advert を含む
[class~="card"]
空白区切りの単語として card を含む
[lang|="en"]
値が en または en-US のように en- で始まる
[aria-label*="advertisement" i]
大文字・小文字を区別せず advertisement を含む

セレクターは記載した属性だけを調べ、ほかの属性を禁止しません。たとえば [data-type="description"][aria-label="Card"] は <div data-type="description" aria-label="Card" title="Details"> にも一致します。追加の title は問題ありません。標準 CSS ではほかの属性が一切ないことを要求できません。

組み合わせセレクター

タグ、クラス、ID、属性条件を空白なしで組み合わせ、同じ要素に適用できます。

セレクター： h2.card__title, div.card.featured, div[data-type="description"], article.card[data-type="advertisement"][aria-label="Advertisement"]

見つかるもの：

  • h2.card__title — card__title クラスの <h2>。
  • div.card.featured — card と featured を持つ <div>。ほかのクラスも許されます。
  • div[data-type="description"] — 指定属性を持つ <div>。ほかの属性も許されます。
  • article.card[data-type="advertisement"][aria-label="Advertisement"] — card クラスを持ち、２つの属性値がそれぞれ指定値と正確に一致する <article>。

子孫セレクター（空白）

別の要素の内側にある要素を深さに関係なく見つけます。

セレクター： .card .btn

見つかるもの：card クラスの要素の内側にある、btn クラスのすべての要素。

子セレクター (>)

別の要素の直接の子を見つけます。

セレクター： .card__body > .card__title

見つかるもの：card__body クラスの要素の直接の子で、card__title クラスを持つ要素。

隣接兄弟セレクター (+)

同じ階層の直後の兄弟を見つけます。

セレクター： #confused-cat + .card__description

見つかるもの：id="confused-cat" の直後にある、card__description クラスの要素。

位置疑似クラス

兄弟内の位置で要素を選びます。

セレクター： .card__actions :nth-child(2)

見つかるもの：card__actions クラスの要素の２番目の子要素。

標準 CSS セレクターには限界があります。属性やクラスの数を列挙なしで指定したり、要素自身のテキスト、内部テキスト、正規表現、属性名のパターンを表したりできません。たとえば [data-*] は標準 CSS ではありません。こうした場合は [data-*] や :attr-name(/^data-/) などを備えた BlockIt の拡張ルールを使えます。BlockIt 構文の資料を見る。

iframe と Shadow DOM とは？ 先頭へ

iframe は別のページに埋め込まれた独立したページです。内容は別文書にあるため、親ページからの通常の検索では直接たどれません。

HTML の iframe の例 
<main>
  <h1>メインページ</h1>
  <iframe src="advertisement.html"></iframe>
</main>

advertisement.html の内容は <iframe> 内の別文書として読み込まれます。

Shadow DOM はコンポーネント内の隔離されたツリーです。ページのほかの部分からマークアップを分離し、閉じたシャドウルートは通常のスクリプトからも隠します。

開発者ツールでの Shadow DOM の例 
<video-player>
  #shadow-root (open)
    <button class="play">再生</button>
</video-player>

ボタンは通常のページツリーではなく、<video-player> のシャドウルート内にあります。

これらはブロッカーにとって検索の境界になります。ルールは主文書だけでなく、アクセス可能な iframe とシャドウルート内でも動く必要があります。すべてのブロッカーが対応するわけではありません。BlockIt は iframe と Shadow DOM 内で CSS セレクターと拡張ルールを適用しますが、XPath は文書内でのみ動作し、Shadow DOM の境界を越えられません。

ルールの管理 先頭へ

作成したルールは現在のサイト用またはドメイン指定なしの一覧に表示されます。ビルダーのルールは編集・削除でき、無効なルールも印付きで残ります。

無効化と削除

ルールを無効にするには

「有効なルール」で「無効化」を押します。ルールは残りますが適用されません。すでに消えた要素を戻すにはページを更新します。

ルールを削除するには

「有効なルール」で「削除」を押します。ページを F5 などで再読み込みすると要素が戻ります。

エクスポートとインポート

エクスポートはルールをファイルへ保存します。インポートはファイルから追加するか現在の一覧を置き換えます。

1

ルールの確認

確認するページで BlockIt を開き、「このサイト用：<ドメイン>」の「ルールを確認」を押します。

保存済みルールが要素を見つけるか確認できます。1 回だけ測定するか、「安定性を確認」で複数回読み込めます。測定中はルールを一時停止し、各回の一致数を表示します。

  • 動作：毎回同じ 1 件以上を見つけます。
  • 不安定：読み込みごとに件数が変わります。
  • 未動作：一致がありません。
  • エラー：実行できませんでした。

現在の基底ドメイン用とドメイン指定なしのルールを確認します。BlockIt は通常の保存時にサブドメインを分けないため、e.mail.ru のルールも mail.ru 用になります。ただし確認対象は診断を開いたページです。正確な結果にはルール作成元のページから実行してください。

確認するのは一致であり、要素の用途ではありません。0 件でなくても、意図した要素だけを見つけた保証はありません。

トラブルシューティング 先頭へ

広告以外のものもブロックされた

セレクターの範囲が広すぎると、広告以外のページ要素も見つけてしまいます。

対処方法：

  • 「ルールの管理」に従い、ルールを削除します。
  • HTML ツリーを上下して、広告だけを含む正確なコンテナーを選びます。
  • 追加前に一致数を確認します。複数の一致は、すべてブロックしたい場合だけ適切です。
ルールが動作しない
  • 原因１：最も外側の要素を選んでいない。HTML ツリーを上にたどり、親コンテナーのセレクターをコピーします。
  • 原因２：動的なクラス名が使われている。コピーしたセレクターが更新後に使えなくなることがあります。「ルールの作成方法」で特徴が不安定だと指定し、StableHTMLFinder やビルダーを試します。
  • 原因３：作成後にページ構造が変わった。現在の HTML と一致数を確認します。ブロックが作り直されたなら、セレクターを再コピーするかビルダーでルールを調整します。
  • 原因４：別のドメイン用のルールだった。「このサイト用」か「ほかのサイト用」か確認します。
セレクターが要素を見つけない
  • セレクターを確認：開発者ツール（F12）の「要素」 / “Elements” タブを開き、Ctrl + F（Mac は Cmd + F）でセレクターを検索します。一致がなければセレクターが正しくありません。
要素を削除するとレイアウトが崩れた
  • 対処：ルールを削除し、「非表示」モードで作り直します。要素の場所が残り、レイアウトが崩れにくくなります。
セレクターの一致が多すぎる

まず件数と実際の要素を確認します。安定したクラスや属性があればセレクターに追加します。それでも不十分なら、テキスト、クラス・属性数、兄弟内の位置、周囲との関係を扱えるルールビルダーを使います。調整後、現在のページと更新後に再確認します。

ページの HTML 構造が分からない

StableHTMLFinder は複数回の読み込みを比較して安定性マップを作ります。検索で対象を見つけ、安定した特徴と周囲の要素を調べてください。

HTML が特に強く難読化されている場合、VPN 接続には異なるページが提供されている可能性があります。差し支えなければ一時的に VPN を切り、再読み込みして解析し直します。必ず改善するわけではありませんが、接続先のページ版との関係を確かめられます。

どの方法でも解決しない

StableHTMLFinder が見つけた安定特徴と BlockIt のビルダーを組み合わせ、対象と周囲の両方を使うルールを手動で作れます。

複数の方法を試しても動作しない、または拡張機能でエラーが出る場合は、BlockIt のお問い合わせフォームから報告してください。ページ URL、ルール、可能ならスクリーンショットを添えてください。
